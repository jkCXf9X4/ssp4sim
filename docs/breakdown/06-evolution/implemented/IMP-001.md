# Deduplicate profiling content between PBS and docs

**Question:** Should the near-verbatim profiling command blocks be removed from the operation-layer profiling leaf so runnable commands live only in `docs/profiling.md`?

**Evidence:** `docs/profiling.md` holds all 9 bash command blocks (build and runtime profiling, output hygiene); the PBS profiling leaf reproduces them with identical structure and nearly verbatim text, and its traceability already names the docs file as the source.

**Change:** Replace the command sections in the PBS leaf with a design-level paragraph (when to profile, which tools, which build modes) and a cross-link to the canonical docs file; keep the traceability and layer comment.

**Risk:** Low — two files, ~50 lines removed from PBS; removed text exists verbatim in docs; no code, build, test, or CI changes; no external references point at the removed content.

**Acceptance:** The PBS leaf is a design/operation artifact with no runnable-command duplication; `docs/profiling.md` is unchanged and canonical.
