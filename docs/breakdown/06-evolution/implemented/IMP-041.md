# Integration test for external SSV/SSM loading

**Question:** Should ssp4sim-layer integration tests exercise external and inline SSV/SSM parameter binding resolution through the analysis-system builder?

**Evidence:** ssp4cpp's external-vs-inline resolution is not directly tested from the ssp4sim layer; the data-processing unit tests are source-agnostic; the nested fixture `signal_nested_parameter_bindings` exercises all four binding scopes but is untested; direct access to a convenience binding struct no longer compiles.

**Change:** Route integration tests through `AnalysisSystemBuilder::build()` on real fixtures, keep data-processing unit tests (cases 1–10), fill the fixture combinatorial matrix minimally, and document the nested-traversal resolution path through the builder.

**Risk:** Low-medium — test files and fixture dirs plus a builder test path; requires FMU stubs for fixtures.

**Acceptance:** Real SSP archives verify correct initial-value overrides, prefixed names, values, and SSV-to-SSM mapping resolution; the non-compiling direct access path is removed.
