# Nested system graph support

**Question:** Should nested (hierarchical) SSP systems simulate end-to-end by resolving boundary-crossing connections and path-prefixed model naming?

**Evidence:** The boundary-crossing flag is never set by the parser, so boundary connections are silently dropped; models inside nested systems get bare names while connections use system-prefixed names; system-level parameter bindings targeting boundary connectors are not applied; the nested fixtures are xfailed. Applied: `flatten_subtree` (tree_builder.cpp) strips the duplicated model-element prefix from connector path segments, so leaf paths are exact SSP hierarchical names and root-level bindings override nested inline sets; the `signal_nested_parameter_bindings` xfail is removed and the root SSV+SSM override (`inner.sine.amplitude` = 2.0) now wins over the inner inline value 1.0 (test_parameter_binding_integration, test_parameter_sets).

**Change:** Set the boundary flag correctly during parsing, resolve boundary connections through the hierarchy in the sim graph builder, use path-prefixed model naming, and apply system-level parameter overrides to boundary connectors. Applied: `flatten_subtree` strips the duplicated model-element prefix from connector path segments so parameter keys bind at the correct hierarchy level (root override wins over nested inline set).

**Risk:** Medium — parser, graph builder, analysis-system builder, and tests; incorrect flattening could produce wrong results (mitigated by unit-testing the flattener); empty prefixes keep flat-SSP tests no-op.

**Acceptance:** `signal_nested_parameter_bindings` executes end-to-end and graduates from xfail (verified: nested root override applies, amplitude 2.0); `dcmotor_nested` already executes end-to-end (component-level bindings, unaffected by this fix); boundary parameter overrides apply; no regression on flat SSPs.
