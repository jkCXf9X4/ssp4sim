# Fix the inline ParameterSet namespace bug in ssp1_ssd.toml

**Question:** Should the wrong namespace prefix for `<ParameterValues>` in the SSP1 SSD binding be corrected so inline system-level parameter sets deserialize?

**Evidence:** The binding declares `namespace="ssv"` but the SSP standard puts the wrapper element in the ssd namespace, so the generated deserializer looks for `ssv:ParameterValues` and never matches; inline parameters are silently dropped and `signal_sine_gain_add/baseline` is a strict xfail (REG-001, previously "root cause unknown").

**Change:** Change the TOML binding to `namespace="ssd"`, regenerate the schema code, rebuild, remove the strict xfail marker, and close REG-001 in the regressions tracker.

**Risk:** Low-medium — one TOML line plus regenerated code; external `.ssv` source-attribute bindings are unaffected; requires regenerating bindings and rebuilding.

**Acceptance:** Inline system-level parameter sets apply correctly; `signal_sine_gain_add/baseline` passes; REG-001 is marked fixed. Component-level bindings (REG-002) are out of scope.
