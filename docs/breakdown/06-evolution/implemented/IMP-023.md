# Variable internal feedthrough storage in the sim graph

**Question:** Should per-connection feedthrough metadata be stored in the sim graph instead of being discarded at transfer?

**Evidence:** The FMI model description provides per-variable dependency data, the analysis graph parses it, but the sim graph pipeline discards it; `direct_feedthrough()` operates on all I/O with a warning that it is "not ok" for selective loop resolution; `ConnectionInfo` has no feedthrough field.

**Change:** Add a `bool is_feedthrough` field to `ConnectionInfo`, populate it during graph building from the analysis dependency data (false for delayed edges), and optionally expose accessors; no consumer changes in this candidate.

**Risk:** Moderate — three files; the new field defaults false so behavior is unchanged; no FMU compatibility risk.

**Acceptance:** Sim graph connections carry correct feedthrough flags derived from FMI data; the full suite passes with no behavioral change; consumers can narrow algebraic-loop iteration.
