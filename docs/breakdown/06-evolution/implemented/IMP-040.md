# Three-layer architecture — Analysis System, Analysis Graph, Simulation Graph

**Question:** Should the partial AnalysisSystem implementation be completed as an explicit three-layer architecture (Analysis System, Analysis Graph factory, Simulation Graph)?

**Evidence:** The partial implementation did not compile (headers missing methods tests and the graph builder call, broken builder code); tests were written against a planned API; the three-layer proposal conflicts with `IMP-039`'s decision that AnalysisSystem owns SCC; the layer-2 factory and eager-loading contract are not documented.

**Change:** Formalize AnalysisSystem as the fully loaded pure-data handoff, promote the analysis graph view to a layer-2 factory producing transient views and `find_algebraic_loops()`, move SCC implementation to layer 2 (layer 1 orchestrates), and document the eager-loading contract.

**Risk:** Medium — analysis module, graph module, simulation handoff, SSP extension layer, decision supersession, module docs, and tests; the main addition is a new factory, not a replacement.

**Acceptance:** Implementation landed as the three-layer architecture (superseding decision written): layer-1 AnalysisSystem API completed, layer-2 AnalysisGraph factory created, all test cases pass, old `graph/analysis/` files deleted.
