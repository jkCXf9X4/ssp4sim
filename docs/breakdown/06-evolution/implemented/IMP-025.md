# Seidel-Jacobi hybrid executor

**Question:** Should a standalone hybrid DAG executor be built that runs Jacobi inside Tarjan SCCs and Seidel across the DAG?

**Evidence:** Jacobi variants ignore data dependencies within a step; Seidel variants under-utilize hardware on parallel subgraphs; Tarjan SCC is already available. Real SSPs mix cycles and chains, and no single executor handles both well.

**Change:** Design a hybrid executor: SCC decomposition of the node graph, Seidel parent-counter scheduling over the SCC DAG, fixed-count Jacobi relaxation within cycles, opt-in via a new executor method, reusing Tarjan, the thread pool, and the serial Seidel algorithm.

**Risk:** Moderate-large blast radius (new module, builder wiring, tests); deterministic with fixed iteration counts; per-invoke SCC overhead acceptable for non-trivially sized graphs.

**Acceptance:** Superseded by the la2 loop-aware hybrid (`IMP-046`), which realizes this candidate's hybrid-scheduling intent in `loop_aware/` — Tarjan SCC partitioning, Jacobi-style relaxation within SCCs, Seidel-style scheduling across. No standalone hybrid module was built; the separate hybrid-DAG design is referenced from `IMP-046`.
