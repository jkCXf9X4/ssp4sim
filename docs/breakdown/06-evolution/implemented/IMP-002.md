# Deduplicate configuration schema tables between PBS and docs

**Question:** Should the four reproduced JSON schema reference tables be removed from the implementation configuration leaf so `docs/configuration.md` is the single schema source?

**Evidence:** `docs/configuration.md` carries the full JSON shape, all four schema tables, validation behavior, and examples; the PBS configuration leaf reproduces the same tables verbatim after stating the full schema lives in docs, and its traceability names the docs file as the source.

**Change:** Delete the full key-reference section and tables from the PBS leaf, condense validation notes to unique content, keep the design-level pipeline section and the abbreviated key list, and link to the canonical docs tables.

**Risk:** Low — two files; removed tables are exact duplicates; no code, build, or test changes; cross-references already point to the docs file.

**Acceptance:** The PBS leaf has no schema-table duplication; the docs file remains the single key reference and its examples are unchanged.
