# Deduplicate fmi2Error/fmi2Fatal cleanup documentation

**Question:** Should the duplicated post-error FMU cleanup note be consolidated to one location?

**Evidence:** Both `tests/README.md` and the handler module leaf state that after `fmi2Error`/`fmi2Fatal`, cleanup frees the instance without calling `fmi2Terminate` so logs keep the original failure as root cause.

**Change:** Keep the canonical note in `tests/README.md` (it documents why tests expect specific log output) and replace the handler leaf's note with a cross-link.

**Risk:** Low — one-line change in the handler leaf.

**Acceptance:** One source for FMU post-error cleanup behavior; handler docs focus on handler responsibilities.
