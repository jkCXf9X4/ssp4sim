# Remove coding style rule list from the implementation decision

**Question:** Should the implementation decision record's duplicated coding-style rule list be replaced by a cross-link to the canonical rule list?

**Evidence:** `docs/development.md` owns the 7 coding style rules; the implementation decision record reproduced them with the same structure and meaning even though its traceability already names the docs file as the source. The decision's context, rationale, and consequences are unique and must stay.

**Change:** Replace the rule list in the decision with a single sentence adopting the conventions documented in `docs/development.md`; keep the rationale and consequences; reword consequences to reference the docs rather than re-list.

**Risk:** Low — one file, ~7 lines removed; the removed list is entirely duplicated.

**Acceptance:** The decision documents why the convention was chosen, not what it is; no rule-list duplication remains.
