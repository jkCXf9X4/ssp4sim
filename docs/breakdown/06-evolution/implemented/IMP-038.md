# Clarify analysis graph vs simulation graph responsibilities

**Question:** Should the analysis graph stop carrying model-to-model edges so each graph holds one clear responsibility?

**Evidence:** `connect_fmus()` adds model-to-model edges, violating the architecture decision and three docs that state "no model-to-model edges"; two superimposed node graphs create ambiguity; nested SSPs (e.g. dcmotor) throw because `get_fmu_connections()` only reads top-level connections; model SCC in the analysis graph becomes trivial without those edges.

**Change:** Remove `connect_fmus()`, derive model-to-model edges in the sim graph builder from the connection graph, repurpose the analysis SCC to the connector/variable graph, and add recursive connection flattening for nested SSPs.

**Risk:** Low-medium — builder files, graph SCC semantics, one SSP extension utility, docs, and tests; the pipeline interface is unchanged.

**Acceptance:** The analysis graph is a pure connector/connection/variable graph per the decision; nested SSPs parse without the hard error; model edges are derived in exactly one place.
