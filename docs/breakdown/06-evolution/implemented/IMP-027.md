# Config item for input storage in output artifacts

**Question:** Should recording include FMU input signal values in CSV/SQLite artifacts behind a config flag?

**Evidence:** Only output areas trigger recorder events; the input area's `flag_new_data()` is gated behind extended logging, so release builds cannot record inputs. There is no config key for input-vs-output recording, and users must correlate separate log files or modify source to debug convergence.

**Change:** Add `simulation.recording.record_inputs` (default false), register each FMU's input storage with the recorder when enabled, and un-gate input `flag_new_data()` behind the flag.

**Risk:** Small — config, model, and builder files; the 10-slot input buffer may overflow at aggressive intervals (documented); default-off preserves existing output.

**Acceptance:** With the flag on, CSV/SQLite contains input and output columns; with it off, output is unchanged; the full suite passes.
