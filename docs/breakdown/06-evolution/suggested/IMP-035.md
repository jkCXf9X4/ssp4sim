# XML signal list with per-sink behavior

**Question:** Should recording support a standalone XML signal list that selects which signals are recorded and overrides per-sink behavior?

**Evidence:** Recording today writes all signals in all storages across all sinks; there is no per-signal or per-sink filtering. The recorder event model is per-storage, not per-variable, and the sink interface has no filtering hooks. SignalStorage already holds the type/position metadata filtering needs.

**Change:** Add a standalone XML signal list (referenced by `simulation.recording.signal_list`) with AND-within-signal/OR-across-signals selection, wildcards, and per-sink subtags; filter at the DataRecorder level with pre-computed per-sink masks; document the schema and the future SSP-embedding boundary.

**Risk:** Medium — a new file format, XML parsing, and filtering logic; per-variable filtering adds hot-path overhead mitigated by pre-computed masks. Backward compatible when the key is absent.

**Acceptance:** Selection by model/storage/variable/type works, omitted attributes wildcard, per-sink overrides apply, an absent list preserves current behavior, and interaction with the input-recording flag is documented.
