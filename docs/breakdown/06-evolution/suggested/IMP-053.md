# Atomic id counter and static max_id on Node for vector indexing

**Question:** Should Node gain an atomic id counter plus a static `max_id` so node access can use a `vector<Node*>` indexed by id, replacing the Invocable id?

**Evidence:** A raw developer note proposes adding an atomic id counter and static max_id to Node for indexing, removing the current Invocable id, and using `vector<pointer> nodes_ptr` with `nodes_ptr[node.node_id]` for faster lookup than an unordered map (unused vector slots are acceptable).

**Change:** Add the id machinery to Node, remove the Invocable id, and simplify node access across the codebase — especially on the hot path.

**Risk:** Medium — node identity changes ripple across the codebase; the hot-path benefit must be measured.

**Acceptance:** Node ids are atomic and max_id is static; node access uses vector indexing; lookup on the hot path is faster than the unordered map; the full suite passes.
