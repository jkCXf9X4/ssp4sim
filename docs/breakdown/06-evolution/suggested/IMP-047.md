# Replace vendored reference SSPs with small in-repo e2e fixtures

**Question:** Should the vendored `resources/reference_ssp` submodule be replaced by a small in-repo e2e fixture set, outsourcing the full reference sweep to `ssp_references`?

**Evidence:** The submodule vendors the whole curated model collection plus generated artifacts into every clone and CI job; high-level Python tests and several C++ unit tests hardcode paths into it; a recorded verification decision (superseded here) declared reference SSP fixtures static in-repo artifacts. `ssp_references` already owns the authoritative models and comparison tooling.

**Change:** Remove the submodule and its recursive CI checkout, author a small fixture set (source/sink, two-FMU, one nested/boundary case) under the repo's own test resources, repoint the Python helpers and C++ tests, keep one smoke sweep, and move the comprehensive cross-engine e2e into `ssp_references`.

**Risk:** Medium — submodule removal plus fixture authoring and repointing across C++ tests, Python helpers, CI checkout, and verification docs; no production behavior change.

**Acceptance:** The full ssp4sim suite is green on the small fixtures; `ssp_references` e2e is green and independent; the superseding decision is recorded and verification-layer docs updated.
