# Unit test coverage for boundary connection resolution

**Question:** Should `resolve_model_key()` and `resolve_connection()` in the sim graph builder get direct unit coverage?

**Evidence:** Those two methods implement nested-SSP boundary-crossing connection resolution and have zero direct tests; coverage is indirect via e2e fixtures that exercise only a subset of the four resolution cases. A boundary-OUTPUT bug was found and fixed during delivery of `IMP-042`, which focused tests would have caught.

**Change:** Make the two private methods testable (protected + test subclass, or test-only friend), add `tests/lib/graph/test_graph_builder.cpp` covering exact/suffix/no-match key resolution and all four connection cases, and optionally add integration tests over the nested fixtures.

**Risk:** Low-medium — test files only, plus a minor visibility change in `graph_builder.hpp`; no production behavior change.

**Acceptance:** All branches of both methods are exercised; CI passes; the Case-3 boundary-OUTPUT scenario has an explicit regression test.
