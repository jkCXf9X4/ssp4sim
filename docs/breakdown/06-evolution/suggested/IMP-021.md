# Implement a working ParallelSeidel DAG scheduler

**Question:** Can the `ParallelSeidel` executor be made functional — replacing the stub `std::runtime_error("This is not implemented")` with a working parallel DAG scheduler?

**Evidence:** The stub throws at `seidel_parallel.cpp:29`; lines 31–88 are dead code referencing removed types. `seidel_serial.cpp` shows the correct DAG traversal. `SeidelNode::nr_parents_counter` is non-atomic (a data race under concurrency). No test or config enables `simulation.executor.seidel.parallel=true`, so the crash path is undocumented.

**Change:** Add thread-safe `SeidelNode` counters, a worker-count constructor, a parallel DAG scheduler using the thread pool, builder wiring, dead-code removal, and a smoke test; verify the pool linkage first.

**Risk:** Moderate blast radius (seidel_parallel, seidel_base, executor_builder, one test, possibly CMake). Data-race and double-enqueue risks are the highest; determinism differs only for side-effecting FMUs. The serial Seidel path is unchanged.

**Acceptance:** `seidel.parallel=true` runs without exception and produces a result CSV; serial Seidel and jacobi smoke tests stay green; valgrind/TSan clean on the DAG path. Deferred by explicit instruction — do not implement without a well-motivated request.
