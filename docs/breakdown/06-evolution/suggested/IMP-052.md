# Executors take ownership of invocables

**Question:** Should every executor take ownership of the invocables passed to it, and should the top-layer refactor be propagated downward?

**Evidence:** A raw developer note records that the top layers of the simulation engine were refactored and must be propagated downward: all executors should take ownership of the invocable passed to them, stepdata responsibilities have changed (some broken out to the executor/resolver), and the design docs may be stale and need updating.

**Change:** Patch all executors to take ownership of their invocables, using the macro-time executors as the reference; fill the missing sections and update the design docs.

**Risk:** Medium — ownership semantics ripple through all executor variants; stale docs must be corrected in the same change. Be cautious delegating tasks that touch the same files.

**Acceptance:** All executors take ownership consistently; stepdata responsibilities match the new split; design docs reflect the refactor; the full test suite passes.
