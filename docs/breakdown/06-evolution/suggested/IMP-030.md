# Remote result ingestion via InfluxDB Line Protocol

**Question:** Should simulation results gain a remote sink emitting InfluxDB Line Protocol so multiple sources can ingest into a shared remote database?

**Evidence:** The operation layer defines InfluxDB Line Protocol as the remote result interface, and the product layer captures a remote ingestion use case. Current releases only support file-backed CSV and local database artifacts.

**Change:** Add a remote result sink serializing records as Line Protocol, define the metadata-to-tag/field mapping, add batching, retry and backpressure, make endpoint and auth configuration explicit, and preserve CSV and local database behavior as defaults.

**Risk:** Medium — a new sink plus an operational dependency on a remote endpoint; retries and partial failures must be handled without corrupting local outputs.

**Acceptance:** Remote export works via Line Protocol; metadata maps consistently; remote write failures surface clearly; documentation references the canonical remote interface.
