# OpenTelemetry distributed observability

**Question:** Should OpenTelemetry tracing be added so distributed simulations are observable as one correlated trace?

**Evidence:** The operation layer defines OpenTelemetry as the distributed observability tier, and the product layer captures the distributed simulation use case. Current logging sinks cover only local overview, archival JSON, and live cutelog navigation.

**Change:** Emit spans for key simulation phases and cross-component calls, propagate trace context across simulation boundaries, attach stable metadata (run id, scenario, component, storage, simulation time), and make the exporter/endpoint configurable without affecting local logging sinks.

**Risk:** Medium — protocol and backend configuration complexity; trace data is not a replacement for local overview or deep-analysis logs.

**Acceptance:** Distributed simulations emit correlated traces; context survives process boundaries; OpenTelemetry can be enabled/disabled independently of local sinks; documentation cites the canonical observability tier.
