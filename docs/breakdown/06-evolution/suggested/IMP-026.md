# Direct rerun pipelined Gauss-Seidel executor evaluation

**Question:** Can a pipelined Gauss-Seidel executor overlap consecutive DAG-chain nodes so node N+1 starts before node N finishes?

**Evidence:** Serial Seidel sums all doStep times for a chain; parallel Seidel helps only independent branches. FMI 2.0 co-simulation does not allow overlapping `fmi2DoStep` access or reading an output before the step returns — the standard is the binding constraint.

**Change:** Document the design evaluation and the reject decision; pursue parallel Seidel (`IMP-021`) and the hybrid executor (`IMP-025`) instead. No code changes.

**Risk:** Very high if implemented without an FMI change (speculative execution requires rollback FMI does not support); no implementation is proposed.

**Acceptance:** A design-evaluation note records why pipelining is not viable under FMI and cross-references `IMP-021` and `IMP-025`. Deferred by explicit instruction — do not implement without a well-motivated request.
