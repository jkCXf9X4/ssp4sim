# Resolver-side two-point input interpolation

- **Question:** Can two-point value interpolation (linear B, cubic Hermite C) be enabled generically in the resolver read path for inputs that resolve between two committed areas?

- **Findings:** The read path is zero-order hold by design and every flat-family read is an exact timestamp match, so interpolation there would be a no-op. A genuine bracketing pair exists only for la2 cross-SCC sub-step reads, delay/`time_offset`-shifted reads, and heterogeneous timesteps; the bracketing helpers exist but are dead code. Derivative storage, forwarding, and application are complete and default-on, so a generic B/C implementation subsumes `IMP-046`'s interpolation half.

- **Result:** Scope decided (both B and C) behind config keys `simulation.executor.interpolate_inputs` (default false) and `interpolation_method` (default `hermite`), with a dedicated `AccessMode::Interp` for la2 cross-SCC edges; gate-off stays bit-identical to today. The next investigation task is the empirical derivative slope check before Hermite is trusted.
