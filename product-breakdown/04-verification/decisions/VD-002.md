# VD-002: Known Xfails Tracked as Pytest Markers
<!-- Layer: 04-verification -->
<!-- Status: Accepted (Partially Superseded) -->

## Context

Two parameter-set variants (`signal_sine_gain_add/baseline`, `dcmotor/baseline`) are known to produce different start values than fixtures declare. These were initially tracked as `strict xfail` markers in the Python test suite.

## Decision

Track known failures as strict pytest xfail markers with documented rationale. Use XPASS detection (pytest reporting) to identify when a previously failing test starts passing.

## Rationale

- Strict xfail markers produce XPASS if the test starts passing, alerting the team
- Markers are colocated with test code, reducing documentation drift
- Simpler than maintaining a separate regressions document for two items

## Consequences

- Regressions document (proposed in IMP-008) should extend this with issue IDs and root cause tracking
- New xfails must include rationale strings
- XPASS events trigger investigation and marker removal

## Resolution

REG-001 (`signal_sine_gain_add/baseline`) was resolved by IMP-018 — the namespace field in `ssp1_ssd.toml` was corrected from `ssv` to `ssd`, fixing the XML deserializer tag lookup. The strict xfail marker has been removed and the test now passes.

REG-002 (`dcmotor/baseline`) was resolved by IMP-019 — component-level parameter binding traversal added to `get_parameter_bindings()` in `ssp.cpp`. The strict xfail marker has been removed and the test now passes.
