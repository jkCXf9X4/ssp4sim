# VD-004: Reference SSP Fixtures Are Static and Version-Controlled
<!-- Layer: 04-verification -->
<!-- Status: Accepted -->

## Context

The reference SSP fixtures under `tests/resources/reference_ssp/` are unpacked, version-controlled SSP archives used by high-level workflow tests. They include a nested Git repository and generated build/ content.

## Decision

Keep reference SSP fixtures as static, version-controlled artifacts in the repository. Follow the fixture management policy in `tests/resources/reference_ssp/AGENTS.md`.

## Rationale

- Static fixtures ensure deterministic test execution across environments
- Version control provides traceability for fixture changes
- AGENTS.md documents the specific rules for editing the fixture tree
- Fixtures are the primary data source for the reference SSP sweep

## Consequences

- Fixture size increases repository size (managed, but requires awareness)
- Generated outputs (build/ content) should not be edited
- Fixture updates require PR review
- Fixtures with FMU binaries must preserve executable permissions
