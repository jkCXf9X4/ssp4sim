# PD-003: DuckDB as Current Local Database Backend
<!-- Layer: 01-product -->
<!-- Status: Accepted -->

## Context

DuckDB recording is the current local database result backend. It requires
DuckDB library linkage and adds a dependency.

## Decision

DuckDB is an optional local database recording backend. It is NOT a replacement
for CSV export; both can operate concurrently on the same event stream. DuckDB
is best treated as a post-run analytical store, not as the long-term answer for
separate live writer and viewer processes.

## Rationale

- DuckDB offers better query capabilities for large simulation datasets
- DuckDB offers better support for dynamic timesteps where all models do not synchronize at each macro step
- Local database is the primary result-artifact category for queryable analysis
- CSV remains the portable export for simplicity and external interchange
- Concurrent operation allows users to adopt DuckDB gradually
- The recording pipeline is designed for multiple sinks
- For live local viewing, SQLite WAL is likely a better future backend because it supports one local writer and concurrent readers in a single file
- For multi-source ingestion, a remote time-series or analytical database is a separate category from local file databases

## Consequences

- DuckDB support requires an additional build dependency
- Users without DuckDB support still get CSV export
- Both formats produce the same data (same event stream, different serialization)
- DuckDB should not be presented as the remote database strategy
