# PD-002: Hot-Path Logging Compile-Time Disable
<!-- Layer: 01-product -->
<!-- Status: Accepted -->

## Context

Logging inside simulation hot paths (step, substep, executor loops) can significantly impact performance. Developers need the ability to compile out hot-path logging for production runs while retaining it for debugging.

## Decision

Hot-path logging is controlled at compile time via the `SSP4SIM_LOG_HOT_PATH` CMake option. When OFF, hot-path log statements are compiled out entirely.

## Rationale

- Compile-time removal eliminates any runtime overhead from disabled log statements
- Developers can toggle between debug and optimized builds without source changes
- Consistent with the project's experimental, performance-aware design posture

## Consequences

- Two build configurations needed for debug vs. optimized runs
- Hot-path log guard macros (`IF_LOG`) required in performance-sensitive code
- Documentation must specify build flags for profiling vs. debugging
