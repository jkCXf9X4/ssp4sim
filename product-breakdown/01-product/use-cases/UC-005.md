# UC-005: Query Local Result Database for Viewer and Run Comparison
<!-- Layer: 01-product -->
<!-- Stable ID: PRO-UC-005 -->

## Description

A user records simulation results to a local database artifact so a viewer or
comparison tool can query typed time-series data without repeatedly parsing CSV.

## Preconditions

- SSP archive exists and conforms to SSP 1.0
- Local database recording is enabled in configuration
- The viewer or comparison tool can open the produced database file

## Flow

1. User configures simulation with local database recording enabled
2. Engine runs simulation with a database recorder sink attached
3. Recorder writes timestamped result data to the configured database artifact
4. User opens the artifact from a local viewer or analysis tool
5. Tool queries bounded time ranges, selected variables, or separate run tables

## Postconditions

- Local database artifact is available in the simulation working directory
- Result data can be queried without scanning a full CSV file
- Multiple runs can be compared through separate per-simulation database files

## Current Support

SQLite WAL is the implemented local database backend. It supports per-simulation
auto-named files for concurrent simulation execution, or an opt-in shared file
for sequential-only workflows.

## Limitations

**No local output format supports safe concurrent multi-writer access except
per-simulation-file SQLite WAL.** This is a SQLite single-writer-per-file
constraint, not a per-table constraint. The following backends are explicitly
unsafe for concurrent execution:

- **CSV**: File-level append race. Never use with multiple simultaneous writers.
- **SQLite WAL (single shared file)**: Write lock serializes all writers
  regardless of table. Never use with multiple simultaneous writers.

Only the per-simulation SQLite WAL approach (one `.sqlite` file per run, named
`{epoch_seconds}_{uuid}.sqlite`) supports concurrent simulation execution
without write-lock contention.

These limitations are documented in REQ-005, CAP-005, the domain model, and
the configuration and usage documentation to prevent future mistakes.
