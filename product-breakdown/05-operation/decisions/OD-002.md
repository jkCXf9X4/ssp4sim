# OD-002: File-Based Output Only For Current Releases
<!-- Layer: 05-operation -->
<!-- Status: Accepted -->

## Context

Simulation output is currently written to the filesystem as CSV files or a
DuckDB database. The desired result-artifact model has three categories: CSV,
local database, and remote database. Only the first two are available today.

## Decision

File-based output only. No streaming, socket, or network output in version 1.
Remote database ingestion is a future category, not an operator-visible feature
in the current release line. When it is added, the canonical remote interface is
InfluxDB Line Protocol (`OD-004`).

## Rationale

- File-based output is the simplest and most portable approach
- No network infrastructure dependencies
- Aligns with the project's narrow runtime surface goal
- CSV and DuckDB both support output to arbitrary filesystem paths
- Remote databases introduce service availability, credentials, batching, retry, and schema-versioning concerns that need a separate operational contract

## Consequences

- Operators needing real-time data must poll output files
- No remote monitoring or dashboard integration
- Storage management (disk space) is the operator's responsibility
- Output is available immediately after simulation completion
- Multi-source ingestion requires an external import path today
