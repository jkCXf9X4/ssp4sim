# OD-004: InfluxDB Line Protocol as Remote Result Interface
<!-- Layer: 05-operation -->
<!-- Status: Accepted -->

## Context

Remote result ingestion needs a stable interface that can support multiple
backend databases and multiple simulation producers. The interface should stay
independent from any specific remote database product.

## Decision

Use InfluxDB Line Protocol as the canonical remote result interface. Remote
result sinks and adapters should accept or emit this line-oriented time-series
format as their external contract. This is a wire-format decision, not a
mandate to use the InfluxDB server product itself.

## Rationale

- Line protocol is compact, text-based, and easy to batch
- It maps naturally onto timestamped simulation results with tags and fields
- It keeps the simulation engine decoupled from any single remote database
- A canonical wire format makes future adapters and integrations easier to share

## Consequences

- Remote database implementations must define a lossless mapping to the line
  protocol contract
- Shared metadata such as run id, source id, model, storage, variable, and
  simulation time must be represented consistently
- Remote ingestion remains a separate feature from the current file-backed
  result paths
