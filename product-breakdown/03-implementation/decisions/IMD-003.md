# IMD-003: Coding Conventions
<!-- Layer: 03-implementation -->
<!-- Status: Accepted -->

## Context

SSP4SIM follows specific coding conventions to maintain consistency across the codebase. These conventions cover formatting, naming, and design philosophy.

## Decision

Adopt the following coding conventions:
- C++ formatting: 4-space indent with braces on the next line
- Class names: PascalCase; functions and files: snake_case
- Includes ordered and local headers grouped consistently under lib/include/**
- No enforced formatter; match surrounding style closely
- Keep changes direct and explicit; minimize duplication without hiding simulation or memory-layout details
- Prefer repository-owned code over patching vendored dependencies
- Root-cause fixes preferred over compatibility shims and broad defensive workarounds

## Rationale

- Consistent codebase reduces cognitive overhead for contributors
- Experimental software benefits from clear root-cause fixes over workarounds
- No enforced formatter keeps the build fast and avoids formatter version drift

## Consequences

- Contributors must manually match surrounding style
- Code review catches formatting issues instead of automated tools
- Repository-owned code ensures clear ownership; vendored patches require explicit justification
