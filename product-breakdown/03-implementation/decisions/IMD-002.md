# IMD-002: Static Library with Minimal Public Headers
<!-- Layer: 03-implementation -->
<!-- Status: Accepted -->

## Context

All engine modules compile into a single static library (`libssp4sim.a`). Public API headers are separated from private headers.

## Decision

Build as a static library. Separate public headers in `lib/public_include/` from private implementation headers in `lib/include/`.

## Rationale

- Static linking avoids shared library versioning concerns for an experimental project
- Public header separation enforces API discipline — if it's not in public_include/, it's not part of the API
- Single link target simplifies the build system

## Consequences

- Consumers must relink when the library changes
- No dynamic loading of internal modules (intentional — flat address space for performance)
- Public API additions require adding to public_include/ and updating the CMake public include directory

## Traceability

- Backward: Architecture decision AD-001 (modular monolith).
- Sources: `lib/CMakeLists.txt`, `lib/public_include/`.
