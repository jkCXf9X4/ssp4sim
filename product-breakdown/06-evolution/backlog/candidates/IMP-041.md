
# IMP-041: Integration test: external SSV/SSM loading

## Lifecycle Stage

Candidate

## Status

Proposed

## Layer

Evolution (primary), 03-implementation (test infrastructure)

## Theme

Add ssp4sim-level integration tests that validate external SSV/SSM parameter file loading via ssp4cpp XML resolution paths, covering ParameterSet and ParameterMapping resolution for external (file-referenced) bindings.

## Evidence

- `lib/ssp4sim/ssp4cpp/ssp.cpp` — `get_parameter_set()` and `get_parameter_mapping()` handle external vs inline resolution but lack direct coverage from ssp4sim-layer tests.
- `tests/lib/core/test_parameter_binding.cpp` — operates at data-processing layer, source-agnostic; does not exercise SSP-archive loading with external SSV/SSM bindings.
- `resources/reference_ssp/models/ssp/embrace/ssp/` — contains real SSP archive with external bindings

## Current Pain Or Risk

The XML parsing resolution for external vs inline ParameterSets and ParameterMappings (in ssp4cpp/ssp.cpp: `get_parameter_set`, `get_parameter_mapping`) is not directly tested from the ssp4sim layer. Unit tests in `test_parameter_binding.cpp` are source-agnostic and do not exercise the full SSP-archive loading path. This creates a verification gap: changes to the external-resource resolution logic may regress without detection at the integration level.

## Proposed Improvement

Evaluate and implement one of the following approaches (scope to be finalized in task contract):
1. Add an ssp4sim-level test that loads a real SSP archive with external SSV/SSM bindings (e.g., `resources/reference_ssp/models/ssp/embrace/ssp/`). This requires that the SSP directory contain all FMU resources, or that ssp4cpp makes FMU loading optional.
2. Add a self-contained test using ssp4cpp's `utils::xml::parse_file` to parse minimal SSV/SSM XML files directly (requires exposing the internal header `xml_deserialize.hpp`).
3. Extend ssp4cpp's existing `test_import.cpp` with more assertions on `parameter_bindings` content from external sources.

## Expected Benefit

Closing the integration-test gap for external SSV/SSM parameter resolution. Regression detection when ssp4cpp's parameter-binding parsing changes. Increased confidence in the SSP-loading pipeline for real-world archives with external references.

## Risk And Blast Radius

- **Option 1 (SSP archive test):** Moderate blast radius — requires FMU resource availability or optional FMU loading in ssp4cpp. May add a test dependency on real SSP files.
- **Option 2 (Self-contained XML):** Low blast radius — requires only exposing an internal header; no external resource dependency.
- **Option 3 (Extend test_import.cpp):** Low blast radius — pure test additions in ssp4cpp's own test file.
- Modules likely affected: `ssp4cpp/ssp.cpp`, `test_parameter_binding.cpp`, `test_import.cpp`, `xml_deserialize.hpp`.
- Risk level: Low-Medium, depending on chosen approach.
