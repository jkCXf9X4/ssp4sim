# IMP-006: Reduce docs/overview.md To Pure Landing Page With PBS Links

Use this template for one backlog-ready improvement candidate.

An improvement candidate is not implementation approval. It needs a scoped task contract before code or documentation changes begin.

## Status

Proposed

## Layer

01-product

## Theme

Condense the product-positioning content in `docs/overview.md` to a minimal landing page that links to `product-breakdown/01-product/` for the full product description, rather than partially duplicating it.

## Evidence

- `docs/overview.md` (17 lines): The first paragraph (lines 5-7) describes SSP4SIM as "a small experimental SSP simulation engine" and positions it relative to "broader simulation environments." Lines 12-14 add more positioning ("useful when the goal is to test SSP-based simulation strategies..."). The file correctly links to `product-breakdown/01-product/capabilities.md` on line 10.
- `product-breakdown/01-product/capabilities.md`: Contains the authoritative product description, capabilities list, and target audience.
- `product-breakdown/01-product/scope.md`: Contains the scope boundaries.
- `product-breakdown/01-product/glossary.md`: Contains the domain model and definitions.
- `readme.md` line 9 links to capabilities.md, and readme.md line 36 links to `docs/overview.md`.

## Current Pain Or Risk

- **Minor duplication**: The product positioning text in `docs/overview.md` replicates what should live (and partially already lives) in the PBS 01-product layer.
- **Blurred ownership**: A reader wanting to understand the product's target audience and scope could read either file and get an incomplete picture. The PBS files are the canonical source; `docs/overview.md` should point there.
- **Drift risk**: If the product positioning changes (e.g., the experimental scope is narrowed), both `capabilities.md` and `overview.md` might need updating.

## Proposed Improvement

1. In `docs/overview.md`, reduce lines 5-14 to a single sentence that states the file's purpose: "This page links to the product-level documentation, installation guide, and usage reference."
2. Keep the existing link to `product-breakdown/01-product/capabilities.md` (line 10).
3. Enhance the landing-page role by adding links to other key entry points: `product-breakdown/01-product/scope.md`, `product-breakdown/01-product/glossary.md`, and the existing `readme.md` link list.
4. Preserve the layer comment and final line pointing to README for detailed docs links.

## Expected Benefit

- Single authoritative source for product positioning (PBS 01-product).
- `docs/overview.md` becomes a clean "start here" landing page with links, not a competing description.
- Eliminates drift point.

## Risk And Blast Radius

- **Blast radius**: 1 file (`docs/overview.md`). ~6 lines of positioning text removed.
- **Risk**: Very low. The positioning text is already present in PBS capabilities.md and readme.md.
- **Dependency**: None.
