# IMP-005: Deduplicate Generated-Data Policy Between Docs And PBS

Use this template for one backlog-ready improvement candidate.

An improvement candidate is not implementation approval. It needs a scoped task contract before code or documentation changes begin.

## Status

Proposed

## Layer

03-implementation

## Theme

Replace the Generated Data Policy section in `docs/development.md` with a cross-link to `product-breakdown/03-implementation/dependency-policy.md`, which owns the authoritative policy on generated/fixture data handling.

## Evidence

- `docs/development.md`, lines 42-60 ("Dependencies And Generated Data" section): Contains specific policy text about generated data (lines 58-60: "Treat build/, unpacked archives, result CSVs, logs, and FMU/SSP binaries as generated or fixture data. Do not normalize, repackage, or rewrite them unless the requested change explicitly requires it.") as well as Python environment guidelines (lines 48-50) and vcpkg setup (lines 44-46).
- `product-breakdown/03-implementation/dependency-policy.md`, lines 38-59 ("Generated Data Policy" section): Contains an expanded version of the same policy with the same items organized as a bullet list (lines 42-46), plus handling instructions for mutable fixtures (lines 49-53) and Python environment (lines 56-59).
- The two sections overlap substantially: generated data handling, Python venv usage, Linux x86_64 assumptions, executable permission preservation.

## Current Pain Or Risk

- **Content drift**: The generated data policy and Python environment guidelines exist in two places with slightly different organization and wording. A developer updating one may miss the other.
- **Boundary violation**: `docs/development.md` is a runnable developer guide. The generated data policy is a stable design/implementation decision that belongs in PBS. The `docs/development.md` version should limit itself to a summary and a link.
- **Reader confusion**: When the policy text diverges, a developer cannot tell which version is authoritative. The PBS file's Traceability does not currently list `docs/development.md` as a source (it lists `vcpkg.json`, `3rdParty/CMakeLists.txt`, `lib/CMakeLists.txt`), suggesting the policy originated in PBS and was later copied to docs.

## Proposed Improvement

1. In `docs/development.md`, replace lines 51-60 (the generated data policy and Python environment details) with a single cross-reference sentence: "See [Dependency Policy — Generated Data Policy](../product-breakdown/03-implementation/dependency-policy.md#generated-data-policy) for the authoritative policy on generated and fixture data, including Python environment guidelines."
2. Keep lines 42-48 in `docs/development.md` (CMake presets, vcpkg, build flags) — those are runnable build instructions belonging in docs.
3. Keep lines 49-50 (venv mention) only if it adds unique value; otherwise let the PBS link cover it.
4. Do not modify `product-breakdown/03-implementation/dependency-policy.md`.

## Expected Benefit

- Single authoritative source for generated data policy (PBS).
- `docs/development.md` stays focused on runnable developer guidance.
- Reduced drift risk.

## Risk And Blast Radius

- **Blast radius**: 2 files (`docs/development.md` and `product-breakdown/03-implementation/dependency-policy.md`). `docs/development.md` loses ~10 lines of policy text.
- **Risk**: Low. The removed text is a subset of content already present in PBS.
- **Dependency**: None. No other files reference the specific lines being removed from `docs/development.md`.
