## Evidence

- `docs/linux_binary_distribution.md` (83 lines): Full runnable documentation of the release pipeline with concrete commands (`cmake --install build --prefix dist/ssp4sim` in Stage 3), workflow file paths, template file paths, and detailed packaging instructions.
- `product-breakdown/05-operation/release-pipeline.md` (59 lines): Uses the same 6-stage structure as the docs version. Most of the content is at the design level (what each stage produces), which is correct. However, Stage 3 (lines 28-31) includes a concrete bash command (`cmake --install build --prefix dist/ssp4sim`) that is directly duplicated from `docs/linux_binary_distribution.md` line 44.
- Traceability in PBS file (line 59): `- Sources: \`docs/linux_binary_distribution.md\`, \`.github/workflows/linux-release.yml\`.` — Correct.

## Current Pain Or Risk

- **Minor duplication**: The bash command in PBS line 30 is a direct copy from the docs file.
- **Blurred boundary**: The 6-stage structure is useful as an organizing principle in PBS, but inclusion of a specific shell command crosses into runnable-doc territory.
- **Drift point**: If the install command changes (e.g., a different prefix or additional cmake flags), two files need updating.

## Proposed Improvement

1. In `product-breakdown/05-operation/release-pipeline.md` Stage 3, remove the bash code block (lines 29-31) that contains `cmake --install build --prefix dist/ssp4sim`.
2. Replace with prose describing the install stage at the design level (e.g., "Install rules copy build artifacts to a staging directory tree under `dist/`.").
3. Preserve the rest of the file, which is already at the correct design level.
4. Preserve the Traceability section.

## Expected Benefit

- PBS stays at design/operations level; docs/ owns the command reference.
- Removes a specific drift point.
- Strengthens the boundary.

## Risk And Blast Radius

- **Blast radius**: 2 files (`product-breakdown/05-operation/release-pipeline.md` and `docs/linux_binary_distribution.md`). PBS loses one 3-line code block.
