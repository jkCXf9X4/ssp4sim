# IMP-036: Unified Analysis Graph Node Vector with Tarjan SCC for Feedthrough Detection

## Status

Proposed — Design Evaluation Only

## Layer

03-implementation (analysis graph builder/module), 02-architecture (graph traversal strategy)

## Theme

Unify the four heterogeneous analysis graph node collections into a single `std::vector<Node*> all_nodes`, run Tarjan SCC on the unified vector, and replace the current per-output BFS-based feedthrough detection with a two-phase SCC-based approach (SCC membership + condensation DAG reachability).

### 2. Current BFS-based `compute_feedthrough()` — code to be replaced

**`analysis_graph_builder.cpp:362-430`** — the full method:

```cpp
void AnalysisGraph::compute_feedthrough() {
    // should be moved to tarjans...
    for (auto &it : this->models) {
        std::string model_name = it.first;
        for (auto &output_connector : it.second->outputs) {
            // BFS: walk children edges from this output connector
            // looking for input connectors of the same FMU
            std::set<Node *> visited;
            std::queue<Node *> queue;
            queue.push(output_connector);
            visited.insert(output_connector);
            while (!queue.empty()) {
                Node *current = queue.front();
                queue.pop();
                for (auto *child : current->children) {
                    if (visited.find(child) == visited.end()) {
                        visited.insert(child);
                        // Check if child is an input connector of the same FMU
                        AnalysisConnector *connector =
                            dynamic_cast<AnalysisConnector *>(child);
                        if (connector != nullptr &&
                            connector->direction == ConnectorDirection::input &&
                            connector->parent_model_name == model_name) {
                            output_connector->is_feedthrough = true;
                            // early exit once feedthrough is found
                            goto next_output;
                        }
                        queue.push(child);
                    }
                }
            }
            next_output:;
        }
    }
}
```

This per-output BFS walks the children graph independently for each output connector. Complexity is O(outputs × edges) per FMU.

## Current Pain Or Risk

1. **Per-output BFS is algorithmically wasteful** (Medium): For each output connector of each FMU, a full BFS walk from that output node is performed, visiting overlapping subgraphs many times. Complexity is O(outputs × edges) rather than O(V + E) for Tarjan.

2. **Heterogeneous collections prevent unified graph analysis** (Medium): The four maps (`models`, `connectors`, `connections`, `model_variables`) lack a single unified traversal vector, so Tarjan SCC — which needs `vector<Node*>` — only sees models. Internal dependency chains (variable → connector → connection → connector → variable) are invisible.

3. **Tech debt comment** (Low): The `// should be moved to tarjans...` comment at `analysis_graph_builder.cpp:361` signals known suboptimal design that should be cleaned up.

4. **Missed optimization opportunity** (Medium): The SCC decomposition is already being computed (in `to_string()`) on a subset of the graph but the result is discarded after debug logging. The same computation on the full graph would enable feedthrough detection, executor scheduling (IMP-025), and init-phase loop detection (IMP-024).

## Proposed Improvement

### Five-Step Implementation Plan

#### Step 1: Unified `all_nodes` vector

Add `std::vector<Node*> all_nodes` to the `AnalysisGraph` class. Populate in the constructor (or a dedicated init method) by collecting pointers from all four maps:

```cpp
// In AnalysisGraph constructor or init():
all_nodes.reserve(models.size() + connectors.size() + connections.size() + model_variables.size());
for (auto& [name, model] : models)   all_nodes.push_back(model);
for (auto& [name, conn] : connectors) all_nodes.push_back(conn);
for (auto& [name, edge] : connections) all_nodes.push_back(edge);
for (auto& [name, var] : model_variables) all_nodes.push_back(var);
```

All types derive from `Node`, so no `dynamic_cast` is needed — direct push to `vector<Node*>` is valid.

#### Step 2: Run Tarjan on `all_nodes`

In `AnalysisGraph::to_string()` (or a new utility method `compute_sccs()`), call `strongly_connected_components()` on the unified vector. Store results as:

```cpp
// Store per-node SCC membership
std::map<Node*, size_t> node_to_scc_id;
std::vector<std::vector<Node*>> sccs =
    ssp4sim::utils::graph::strongly_connected_components(all_nodes);
for (size_t i = 0; i < sccs.size(); ++i) {
    for (auto* n : sccs[i]) {
        node_to_scc_id[n] = i;
    }
}
```

The SCC result now includes connectors, connections, and model_variables as full graph participants.

#### Step 3: Build condensation DAG

Create a DAG where each SCC is a meta-node. Edges from SCC A to SCC B exist when any node in A has a child in B:

```cpp
// Build SCC-level DAG edges
std::set<std::pair<size_t, size_t>> scc_edges;
for (auto* node : all_nodes) {
    size_t src_scc = node_to_scc_id[node];
    for (auto* child : node->children) {
        size_t dst_scc = node_to_scc_id[child];
        if (src_scc != dst_scc) {
            scc_edges.insert({src_scc, dst_scc});
        }
    }
}
```

The condensation DAG is guaranteed acyclic by Tarjan's properties.

#### Step 4: Rewrite `compute_feedthrough()` — two-phase approach

Replace the per-output BFS with a two-phase SCC-based detection:

**Phase 1 — SCC membership (cyclic feedthrough)**:
```cpp
for (auto &[model_name, model] : models) {
    for (auto *output : model->outputs) {
        size_t output_scc = node_to_scc_id[output];
        for (auto *input : model->inputs) {
            size_t input_scc = node_to_scc_id[input];
            if (output_scc == input_scc) {
                // Same SCC: cycle implies transitive dependency
                output->is_feedthrough = true;
                break;
            }
        }
    }
}
```

**Phase 2 — Condensation DAG reachability (acyclic feedthrough)**:
```cpp
// For each output without Phase 1 match, check reachability in condensation DAG
// Use DFS/BFS on the SCC-level DAG (which is acyclic)
// If output's SCC can reach input's SCC → feedthrough
```

This handles both cyclic feedthrough (same SCC, Phase 1) and acyclic feedthrough (output's SCC can reach input's SCC in the condensation DAG, Phase 2).

#### Step 5: Remove old per-output BFS code

Delete the per-output DFS loop (lines 392-428 of `analysis_graph_builder.cpp`) and the associated `goto` label. The `// should be moved to tarjans...` comment is removed after the new implementation is verified.

## Expected Benefit

- **Algorithmic improvement**: O(V+E) Tarjan + O(SCC²) condensation DAG construction + O(SCC × outputs) reachability queries vs O(outputs × edges) per-FMU BFS. For typical SSPs with 10-100 FMUs and proportional connectors, this is a meaningful reduction.
- **Code clarity**: Removes the `// should be moved to tarjans...` tech debt comment and the complex BFS-with-`goto` pattern.
- **Single canonical graph representation**: The unified `all_nodes` vector becomes the standard source of truth for any analysis-graph-wide algorithm.
- **SCC decomposition is reusable**: The stored SCC membership map can be consumed by the executor layer for:
  - IMP-024 (init-phase loop iteration — SCC groupings for algebraic loops)
  - IMP-025 (hybrid executor — SCC-level DAG for mixed mode scheduling)
- **Debug/visualization benefit**: Tarjan output in `to_string()` now reflects the full graph structure including connections, connectors, and model variables.

## Risk And Blast Radius

- **Blast radius files**:
  - `analysis_graph.hpp` — add `all_nodes` member, SCC-related members
  - `analysis_graph.cpp` — construct `all_nodes`, run Tarjan, build condensation DAG
  - `analysis_graph_builder.hpp` — may need new method signatures
  - `analysis_graph_builder.cpp` — `compute_feedthrough()` rewrite (primary change)
- **Implementation effort**: Low-medium (~150-250 lines across 4 files)
- **Regression risk**: Medium — feedthrough correctness must match existing BFS for all SSP fixtures. The two-phase SCC approach should produce identical results for all cases, but the Phase 2 condensation DAG reachability check needs careful verification against the current BFS behavior.
- **No external interface changes**: The `AnalysisConnector::is_feedthrough` field and its consumption by `GraphBuilder` remain unchanged. No API/ABI breakage.
- **Model variable ordering risk**: The construction of `all_nodes` is non-deterministic if map iteration order matters. Use `std::map` (ordered by key) to ensure deterministic ordering.
- **Memory risk**: Negligible — storing additional `Node*` pointers (not copies).

**Mitigation strategy for regression risk**: Write a migration test (see Task Contract Seed item 6) that constructs a known graph, runs both BFS-based and SCC-based `compute_feedthrough()`, and asserts identical `is_feedthrough` values for all output connectors. This ensures the replacement is byte-identical in behavior.

## Suggested Priority

Low-Medium — solves real algorithmic tech debt and provides reusable infrastructure, but the current BFS works correctly for all known SSPs. The primary value is enabling downstream improvements (IMP-024, IMP-025) and removing the "should be moved to tarjans" specter.

## Notes

- The condensation DAG reachability check (Phase 2) must be proven equivalent to the current BFS for all graph topologies. The current BFS walks children edges from each output looking for same-model inputs. In the SCC approach, Phase 2 checks SCC reachability in the condensation DAG. This should be equivalent because any path from output to input in the original graph corresponds to a path in the condensation DAG (each SCC is contracted to a single node, and inter-SCC edges preserve direction).
- The SCC decomposition may also be useful for `to_string()` debug output — the unified `all_nodes` makes the SCC output more representative of the full graph structure.
- If memory overhead is a concern, `all_nodes` could be computed lazily or as a view rather than a stored vector. Storing it is recommended for simplicity in the first implementation.
- Consider thread safety if `all_nodes` is accessed from multiple threads (unlikely in current usage, but worth noting if executor layer accesses it).
