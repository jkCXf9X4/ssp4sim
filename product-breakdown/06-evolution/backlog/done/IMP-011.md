# IMP-011: Remove Coding Style Rules List From PBS Architecture Decision — Link To Docs Instead

## Status

Proposed

## Layer

03-implementation

## Theme

The coding style rule list in `product-breakdown/03-implementation/decisions/IMD-003.md` duplicates `docs/development.md`. Replace the enumerated list with the decision's rationale and a cross-link to the canonical rule list in docs.

## Evidence

- `docs/development.md`, lines 28-40: Contains 7 coding style rules (4-space indent, PascalCase/snake_case, include ordering, no enforced formatter, direct changes, prefer repository-owned code, root-cause fixes).
- `product-breakdown/03-implementation/decisions/IMD-003.md`, lines 11-18: Contains the same 7 rules in slightly different wording but the same structure and meaning.
- The decision's Traceability Sources field (line 35) already says `docs/development.md (Coding Style section)` — correctly identifying the source, yet the decision reproduces the content anyway.
- The decision's Context (lines 6-7), Rationale (lines 21-24), and Consequences (lines 27-30) are unique, valuable content that should stay.

## Current Pain Or Risk

- **Drift risk**: Adding, removing, or rewording a style rule requires edits in two files.
- **Boundary violation**: An architecture decision record (PBS 03-implementation/decisions/) should document *why a convention was chosen*, not *what the convention is*. The "what" belongs in developer documentation.
- **Misleading Traceability**: The Sources field says "see docs/development.md" while the file reproduces the same content, contradicting its own cross-reference.

## Proposed Improvement

1. In `product-breakdown/03-implementation/decisions/IMD-003.md`, replace the 7-item bullet list under ## Decision (lines 11-18) with a single sentence: "Adopt the coding conventions documented in `docs/development.md` (Coding Style section)."
2. Preserve the Context, Rationale, Consequences, and Traceability sections unchanged — these are the unique value of the decision record.
3. The Consequences section (lines 27-30) may need slight rewording to say "Contributors must manually match surrounding style per the guidelines in docs/development.md" rather than listing the rules again.

## Expected Benefit

- Architecture decision becomes what it should be: *why* a convention was chosen, not *what* it is.
- Single source of truth for style rules (`docs/development.md`).
- Reduced drift risk.

## Risk And Blast Radius

- **Blast radius**: 1 file (`product-breakdown/03-implementation/decisions/IMD-003.md`). ~7 lines removed.
- **Risk**: Low. The removed list is entirely duplicated from `docs/development.md`.
- **Dependency**: No other files reference the content of IMD-003 specifically.

## Suggested Priority

High — architecture decisions with stale content erode trust in the decision record system.
