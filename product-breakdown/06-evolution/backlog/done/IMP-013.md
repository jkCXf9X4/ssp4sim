# IMP-013: Consolidate Fmi4c Mode-Bit Documentation To One Canonical Location

## Status

Proposed

## Layer

03-implementation

## Theme

The same note about fmi4c loader changing `.so` mode bits appears in three files. Consolidate to the dependency policy (the natural policy owner) and cross-link from other locations.

## Evidence

Three occurrences of the same factual note:

1. `product-breakdown/03-implementation/dependency-policy.md`, line 53: "The fmi4c loader marks Linux shared libraries executable before dlopen -- loading Git-tracked fixtures directly could dirty the working tree."
2. `product-breakdown/04-verification/test-strategy.md`, line 35: "fmi4c loader may dirty Git tracked fixtures by changing `.so` mode bits -- prefer copying mutable fixtures to temp directories."
3. `tests/README.md`, lines 68-71: "The fmi4c loader marks Linux shared libraries executable before `dlopen`, so loading tracked fixtures directly could dirty Git by changing `.so` file mode bits. Prefer tests that copy mutable fixtures into a temporary directory before loading them."

## Current Pain Or Risk

- **Triple maintenance**: Any update to the explanation must be made in three files.
- **No canonical anchor**: A developer encountering this behavior has to search three locations to understand the full picture. The most detailed version is in `tests/README.md`, but the policy ownership belongs to `dependency-policy.md`.

## Proposed Improvement

1. Keep the canonical explanation in `product-breakdown/03-implementation/dependency-policy.md` (the natural policy owner for vendored dependency behavior). Expand the existing sentence to be as thorough as the `tests/README.md` version.
2. In `product-breakdown/04-verification/test-strategy.md`, replace the sentence with: "See `03-implementation/dependency-policy.md` for the fmi4c mode-bit issue."
3. In `tests/README.md`, replace the paragraph with: "See `product-breakdown/03-implementation/dependency-policy.md` for the fmi4c mode-bit issue."

## Expected Benefit

- Single policy owner for dependency behavior explanations.
- Test strategy and test README point to the canonical source rather than reproducing it.

## Risk And Blast Radius

- **Blast radius**: 3 files, minor text changes.
- **Risk**: Low. Text changes only. The policy file keeps its current content (potentially expanded).

## Suggested Priority

Medium — low effort, straightforward consolidation.
