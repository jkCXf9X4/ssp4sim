# IMP-033: Refactoring & Cleanup of Graph Builder Files

## Status
Proposed

## Theme
Refactoring and cleanup of `analysis_graph_builder.cpp` and `graph_builder.cpp` to improve readability, consistency, and maintainability.

## Motivation
Both builder files contain long monolithic `build()` methods, inconsistent patterns, dead/commented-out code, and design friction points that make them harder to work with than necessary. Cleaning them up reduces cognitive load for future development and enables safer downstream changes.

## Files in Scope
- `lib/include/graph/analysis/analysis_graph_builder.cpp`
- `lib/include/graph/graph_builder.cpp`

## Associated Headers
- `lib/include/graph/analysis/analysis_graph_builder.hpp`
- `lib/include/graph/graph_builder.hpp`

## Findings

### Finding 1: Dead commented-out code in `analysis_graph_builder.cpp`
**Location**: Lines 277–323 (final 47 lines)

A large block of commented-out code implements "internal connections" (FMU-internal dependency wiring). It references types (`SimNode`, `Connector::create_name`) and patterns that may no longer exist or be relevant.

**Recommendation**: Either remove the dead block entirely, or if the functionality is intended for future use, extract it to a documented issue/ticket and remove the comment.

**Risk**: Low — removal is safe.

### Finding 2: Parameter/member shadowing in `analysis_graph_builder.cpp`
**Location**: Methods `create_models`, `create_connectors`, `create_connections` (lines 27, 52, 125)

Each method takes `ssp4cpp::Ssp &ssp` as a parameter, but the class already stores `ssp4cpp::Ssp *ssp` as a member. The `build()` method uses `*ssp` (the member), while the individual create methods use the parameter.

**Recommendation**: Choose one pattern — either remove the parameter and use the member consistently, or rename the parameter (e.g., `ssp_ref`) to avoid shadowing.

**Risk**: Low-medium. Option A changes method signatures.

### Finding 3: Unused return value in `analysis_graph_builder.cpp`
**Location**: Line 172 in `build()`

```cpp
auto model_variables = create_model_variables(fmu_handler->fmu_ref_map);
```

The `model_variables` local variable is never used after creation. The `create_model_variables` method itself creates a map that is returned but immediately discarded.

**Recommendation**: Either remove the call and method if genuinely unused, or document its purpose with a TODO.

**Risk**: Low — check for external callers first.

### Finding 4: Inconsistent include ordering in `analysis_graph_builder.cpp`
**Location**: Lines 1–15

Local project includes are interleaved with standard library includes, and another batch of local includes appears after the standard library block.

**Recommendation**: Group includes consistently: local header → project headers → standard library → third-party.

**Risk**: Very low — purely cosmetic.

### Finding 5: Long monolithic `build()` method in `analysis_graph_builder.cpp`
**Location**: Lines 166–273 (~108 lines)

The `build()` method performs multiple distinct phases sequentially:
1. Create models, connectors, connections, model variables
2. Connect FMUs (hierarchical parent-child)
3. Attach connectors to models
4. Create connections between connectors (with derivative forwarding logic)

**Recommendation**: Extract each phase into a private helper method (e.g., `connect_fmus()`, `attach_connectors_to_models()`, `wire_connections()`).

**Risk**: Low-medium. Requires adding private methods to the header.

### Finding 6: Inconsistent error message format in `analysis_graph_builder.cpp`
**Location**: Lines 199–200, 221–223, 236–238

Some error messages use the `[{func}]` prefix convention while others do not.

**Recommendation**: Standardize all error log messages to use `[{func}]` prefix with `__func__`.

**Risk**: Very low — cosmetic/logging only.

### Finding 7: Use of C++ alternative tokens (`or`) in `analysis_graph_builder.cpp`
**Location**: Lines 219, 234

Uses `or` instead of `||`. The rest of the codebase uses `||`.

**Recommendation**: Replace `or` with `||` for consistency.

**Risk**: Very low.

### Finding 8: Long monolithic `build()` method in `graph_builder.cpp`
**Location**: Lines 22–149 (~128 lines)

The `build()` method performs multiple distinct phases:
1. Create FMU models from analysis models
2. Open start-value log file
3. Create data storage areas with connector wiring
4. Wire connections between models
5. Allocate input/output areas and register with recorder
6. Create model parent-child connections

**Recommendation**: Extract each phase into a private named method.

**Risk**: Low-medium. Same considerations as Finding 5.

### Finding 9: Repeated causality checks in `graph_builder.cpp`
**Location**: Lines 48–52 and 77–90

The causality of each connector is checked twice in the same loop iteration — first to determine the storage area index, then again to assign to `inputs`, `outputs`, or `parameters`.

**Recommendation**: Consolidate into a single switch/if-else chain per connector.

**Risk**: Low — purely structural.

### Finding 10: Unsafe `static_cast` usage in `graph_builder.cpp`
**Location**: Lines 45, 97, 98, 124

Uses `static_cast<FmuModel *>` to downcast from `Invocable*`. If the `models` map ever contains a non-`FmuModel` type, this is undefined behavior.

**Recommendation**: Store `unique_ptr<FmuModel>` directly in the map, use `dynamic_cast` with a null check, or add an `as_fmu_model()` virtual method.

**Risk**: Medium — changing the map value type affects the class interface.

### Finding 11: `start_value_log_file` declared early, used late in `graph_builder.cpp`
**Location**: Line 40 (declaration), used at line 74

The `std::ofstream` is opened at line 40 but only first written to at line 74.

**Recommendation**: Move the declaration closer to first use, or wrap in a narrower scope block.

**Risk**: Very low.

### Finding 12: Unnecessary `std::move` on return value in `graph_builder.cpp`
**Location**: Line 153

```cpp
return std::make_unique<Graph>(...);
```

`std::make_unique` already returns a prvalue; `std::move` is redundant.

**Recommendation**: Remove `std::move` for clarity.

**Risk**: Very low.
