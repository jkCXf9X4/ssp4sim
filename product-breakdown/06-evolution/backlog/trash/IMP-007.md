# IMP-007: Jacobi Hybrid Execution — Evaluate Direct-Feedthrough Correctness

## Status

Proposed

## Layer

05-operation (executor semantics), 06-evolution (new variant)

## Theme

Executor naming consistency and direct-feedthrough correctness analysis for Jacobi variants.

## Evidence


- `lib/include/model/model_fmu.cpp` — `FmuModel::step()` bundles `pre()` (set inputs), `step_until()` (advance FMU), and `post()` (read outputs) into a single call. The executor cannot interleave these phases.

- `lib/include/model/model_fmu.cpp:L104` — `direct_feedthrough()` method has a log warning: `"This solution is not ok. Doing direct feedthrough for all variables will overwrite inputs with outputs that are unset."`

- `lib/include/execution/executor.cpp:L39` — Init-phase comment: `"Do NOT implement direct feedthrough for CO-Simulation"` with link to FMI forum discussion.

- `product-breakdown/06-evolution/risks/RISK-001-jacobi-hybrid.md` — Original risk documentation.

## Current Pain Or Risk

3. **Cannot hybridize**: Because `FmuModel::step()` bundles pre/step/post, an executor cannot implement a "hybrid" approach where direct-feedthrough connections are resolved within a single step while non-direct-feedthrough connections use normal Jacobi. The `pre()` and `post()` methods are public on `FmuModel` but the executor API (`Invocable::invoke(StepData)`) only exposes the combined step.

## Proposed Improvement

3. **Extract a design sketch for a hybrid executor** variant that separates pre/step/post at the `Invocable` interface level. This would enable an executor to:
   - Set inputs on all FMUs
   - For direct-feedthrough FMUs: read outputs immediately
   - For non-direct-feedthrough FMUs: step, then read outputs
   - This handles algebraic loops within one step without requiring Newton iteration.

## Expected Benefit

- Provides a clear path for hybrid execution without committing to implementation.
- Makes executor semantics self-documenting.

## Risk And Blast Radius

- Hybrid executor sketch is purely documentation; no implementation risk.
- **Blast radius**: Low for design sketch.

## Suggested Priority

Medium — direct-feedthrough gap is documented but not resolved.

## Notes

- The FMI standard co-simulation interface explicitly does not guarantee algebraic loop resolution within one communication step. The hybrid approach discussed here would go beyond the standard's minimum requirements.
- The `direct_feedthrough()` method in FmuModel exists but has a warning that it overwrites unset outputs. This method is not called by any current executor — it exists for manual use only.
