# IMP-001: Refactoring and Cleanup of `sim_graph_builder.cpp`

**Target files:**
- `lib/include/pre/3_simulation/sim_graph_builder.cpp`
- `lib/include/pre/3_simulation/sim_graph_builder.hpp`

## Overview

The `GraphBuilder` class (487 lines in `sim_graph_builder.cpp`) converts an analysis graph into executable `FmuModel` instances with wired connections and dependency edges. Code inspection revealed 12 refactoring opportunities spanning extraction, encapsulation, naming, and decomposition concerns. No behavioral changes are intended — all items preserve existing semantics.

The full refactoring plan with code references and detailed analysis is at `.opencode/dev_harness_plans/2026-07-03_074451-REFAC-SIM-GRAPH-BUILDER-plan.md`.

---

## Refactoring Items

### HIGH PRIORITY

#### H1. Extract system boundary tracing into shared helper

| Field | Value |
|---|---|
| **Problem** | Lines 204–233 in `wire_connections()` and lines 410–443 in `derive_model_edges()` contain nearly identical code: a `for (int depth = 0; depth < 16; ++depth)` loop that walks `resolved_peer → next_conns → next_peers → resolved_peer` to trace through system boundary connectors. |
| **Solution** | Extract into a private static/non-member helper: `analysis::SspModelNode* trace_boundary_connectors(analysis::SspConnectorNode* peer, int max_depth)`. |
| **Risk** | Low — pure extraction, no behavioral change. |
| **Test Impact** | None — both call paths exercised through existing coverage. |
| **Dependency** | None (independent); prerequisite for L3. |

#### H2. Extract `find_peer_model` logic into shared helper

| Field | Value |
|---|---|
| **Problem** | `wire_connections()` has a local lambda `find_peer_model` (lines 153–163); `derive_model_edges()` (lines 393–408) has the same logic inline without the lambda wrapper. |
| **Solution** | Extract into a shared private helper: `analysis::SspModelNode* find_peer_model_node(analysis::SspConnectorNode* conn_node)`. |
| **Risk** | Low — mechanical extraction. |
| **Test Impact** | None. |
| **Dependency** | None (independent); prerequisite for L3. |

#### H3. Extract `dynamic_cast<FmuModel*>` into helper

| Field | Value |
|---|---|
| **Problem** | Pattern `dynamic_cast<FmuModel*>(model.get())` appears **9 times** (lines 37, 96, 242, 344, 375, 396, 428, 453, 475). Repetitive and error-prone. |
| **Solution** | Add private helper: `FmuModel* as_fmu_model(const std::string& name)` or similar. |
| **Risk** | Low — mechanical replacement. |

#### H4. Remove redundant `std::move(models)` in `build()` return

|---|---|
| **Problem** | Line 48: `return std::move(models);` — in C++17, `std::move` on a local variable in a return statement is redundant and may inhibit NRVO. |

| **Risk** | Very low — well-understood C++17 behavior. |
| **Test Impact** | None. |
| **Dependency** | None (independent). |

## Open Considerations

1. **Naming convention consistency**: The codebase has mixed conventions (`canInterpolateInputs` vs `record_inputs`, `maxOutputDerivativeOrder`). Before L1, confirm snake_case is the dominant convention.
2. **External `FmuModel` consumers**: Before implementing L1, enumerate all files accessing `canInterpolateInputs`.
3. **Test coverage adequacy**: Existing unit tests don't exercise `GraphBuilder::build()` end-to-end with a real graph. H1–H3, M3, L3 extraction changes would benefit from broader integration-level test coverage.
4. **Memory/Cache effects**: H1/H2 extraction adds an indirect call. For graphs with thousands of connections, this could have measurable performance impact. Profile before/after if performance is a concern.
