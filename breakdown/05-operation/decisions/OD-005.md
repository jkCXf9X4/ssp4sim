# OD-005: OpenTelemetry as the Distributed Observability Tier
<!-- Layer: 05-operation -->
<!-- Status: Accepted -->

## Context

Distributed simulations need cross-process visibility that local terminal, file, JSON, and cutelog sinks cannot provide on their own. A trace-oriented tier must carry context across process boundaries and remain separate from the local logging profile.

## Decision

Use OpenTelemetry as the distributed observability tier for multi-process or multi-service simulations. This is the contract for correlating spans and trace context across simulation components.

## Rationale

- OpenTelemetry is designed for distributed tracing and cross-service correlation
- It complements local logs instead of replacing them
- A standard observability contract reduces coupling between simulation code and any specific backend

## Consequences

- Trace context propagation becomes part of distributed simulation design
- OpenTelemetry metadata must stay consistent across components
- The feature is separate from the current local JSON and cutelog sinks
