# AD-002: fmi4c for FMI Adapter Layer
<!-- Layer: 02-architecture -->
<!-- Status: Accepted -->

## Context

FMU shared libraries are loaded at runtime using POSIX dlopen. The fmi4c library provides a C adapter that wraps FMI 2.0 function pointer resolution, model description parsing, and lifecycle management.

## Decision

Use fmi4c as the FMI adapter layer. FMU .so files are loaded via fmi4c which handles platform-specific dlopen mechanics and FMI function pointer binding.

## Rationale

- fmi4c provides a tested abstraction over raw dlopen/dlsym for FMI 2.0
- Vendored as a 3rdParty dependency — no external runtime dependency
- Handles platform-specific loading quirks (e.g., Linux shared library mode bits)

## Consequences

- fmi4c is vendored and built as part of SSP4SIM — security patches require manual vendor update
- FMU loader behavior (dlopen mode bits) affects Git tracked fixtures (see tests/README.md)
- No sandboxing for FMU vendor code — runs in-process with full privileges
- fmi4c adapter tests exist in `tests/lib/core/test_fmi4c_adapter.cpp`
