# REQ-012: Configurable Recording Behavior
<!-- Layer: 01-product -->
<!-- Stable ID: PRO-REQ-012 -->

## Description

The engine MUST support configurable recording behavior: recording input signals alongside outputs (`simulation.recording.record_inputs`), blocking producers when the recorder queue is full (`simulation.recording.wait_for`), and logging initial start values (`simulation.log.start_values`).

## Rationale

Closed-loop analysis needs input traces alongside outputs; large runs need backpressure control against the recorder queue; reproducible research needs the initial values actually applied to the FMUs to be captured.

## Acceptance Criteria

- `simulation.recording.record_inputs=true` records input variables to the configured sinks; defaults to `false`
- `simulation.recording.wait_for=true` blocks the producer when the recorder queue is full; defaults to `false`
- Initial start values are written to the configured start-values log file (default `start_values.csv` in the working directory)

## Constraints

Input recording uses a fixed-size input buffer (10 slots). At the default recording interval (every timestep), simulations with more than 10 steps can overflow the input buffer and silently drop input events. Use `simulation.recording.wait_for` or a larger interval to avoid loss under these conditions.
