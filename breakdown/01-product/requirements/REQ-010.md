# REQ-010: Execution Strategy Variants and Tuning
<!-- Layer: 01-product -->
<!-- Stable ID: PRO-REQ-010 -->

## Description

The engine MUST support the documented execution strategy variants and tuning knobs: Gauss-Jacobi serial and parallel (TBB, spin-wait, futures), Gauss-Seidel serial and parallel, loop-aware execution, and custom delay-oriented executors. Thread-pool size, forward-derivative forwarding, and sub-step size MUST be configurable.

## Rationale

Experimentation with execution strategies is a core project purpose. The variant set and tuning knobs let developers explore coupling behavior, loop handling, and parallel performance from configuration without rebuilds.

## Acceptance Criteria

- `simulation.executor.method` selects `jacobi`, `seidel`, `custom_delay`, `custom_delay_partial`, or `loop_aware`; unknown methods are rejected
- `simulation.executor.jacobi.parallel` selects parallel Jacobi; `simulation.executor.jacobi.method` selects 1=TBB, 2=spin-wait, 3=futures
- `simulation.executor.seidel.parallel` selects parallel Gauss-Seidel
- `simulation.executor.thread_pool_workers` controls the parallel worker pool size
- `simulation.executor.forward_derivatives` toggles derivative forwarding to connected models
- `simulation.executor.sub_step` allows a sub-step smaller than the configured timestep for delay-oriented execution
