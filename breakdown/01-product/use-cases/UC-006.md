# UC-006: Ingest Results into a Remote Database
<!-- Layer: 01-product -->
<!-- Stable ID: PRO-UC-006 -->

## Description

A user sends simulation results to a remote database so runs from multiple
machines or simulation producers can be ingested into one shared store.

## Preconditions

- SSP archive exists and conforms to SSP 1.0
- A remote result database is available
- Authentication, schema ownership, batching, and retry behavior are configured

## Flow

1. User configures simulation with a remote database result sink
2. Engine runs simulation and emits timestamped result batches
3. Remote sink writes batches to the configured database
4. Shared viewers or dashboards query data across simulation sources
5. Operators compare runs by source, model, variable, and time range

## Postconditions

- Simulation results are available in a shared database
- Multiple producers can contribute to the same result history
- Central dashboards and comparison jobs do not need local artifact access

## Current Support

This use case is not implemented. Current releases produce file-based CSV and
local database artifacts only. Remote ingestion requires a new sink,
configuration schema, dependency decision, and operational contract. The
canonical remote interface is InfluxDB Line Protocol.
