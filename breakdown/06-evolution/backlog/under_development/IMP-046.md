# IMP-046: la2 hybrid — warm-started SCC sub-step iteration and sub-step input interpolation

## Lifecycle Stage

Under Development

## Status

In Development

## Layer

03-implementation (executor execution path), 02-architecture (la2 stack data flow)

## Theme

Interpolate the inputs of the substep scc

Speed up the la2 (loop-aware) hybrid scheduler by reducing the cost of the per-timestep
algebraic-loop relaxation: (a) warm-start the SCC sub-step iteration from the latest committed
values so fewer sub-iterations are needed to converge, and (b) evaluate using the latest SCC
input values + their derivatives to interpolate SCC inputs during the sub-step phase.

## Evidence

Measured in `resources/embrace/executor_timing_analysis.md` (2026-09-16, embrace scenario,
6 models, 4-node SCC):

- The hybrid's slowdown vs an equivalent fine-step jacobi is per-call model wall-clock
  inflation (~1.3–1.7× in full runs; up to ~3.5× in the pinned short benchmark), caused by the
  4× sub-step sweep (`LinearSubstepExecutor` -> `invoke_group_parallel`) with barrier sync and
  sub-step-boundary resolver sampling — not by extra FMU work.
- Forward derivatives are a convergence/accuracy mechanism, not a cost: disabling
  `forward_derivatives` makes runs slower (12.6× at dt=0.01, 2.7× at dt=0.0025, 1.26× in la2),
  because `canInterpolateInputs` FMUs grind internally without an input derivative.
- `simulation.recording.record_derivatives` (IMP-027-style opt-in, added 2026-09-16) now exports
  per-signal `.d1` columns, and the check confirmed derivatives are correctly anchored to their
  (sub-)timestep in both executors — so any warm-start/interpolation change can be verified
  against recorded values.

## Current Pain Or Risk

1. **Wasted relaxation work** (Medium): each macro step re-converges the SCC from the previous
   macro boundary. Because sub-steps sample the previous sub-step's commitments, the iteration
   already relaxes toward the new operating point — but the *number* of sub-iterations is fixed
   (`iterations` = SCC node count by default), not driven by a warm start or convergence. If the
   iteration began closer to the converged values (e.g., seeded from the latest committed
   values), fewer sub-iterations would suffice, cutting the dominant cost of the hybrid.
2. **No input interpolation within the SCC** (Low-Medium): cross-SCC inputs are sampled at the
   latest committed value once per sub-step; the sub-step phase cannot interpolate SCC inputs or
   their derivatives between the sampled points. For FMUs with `canInterpolateInputs`, providing
   the derivative (already forwarded by the resolver) is what keeps internal stepping cheap —
   the potential of using it for sub-step interpolation is unexplored.
3. **Correctness/perf tradeoff unevaluated** (Low-Medium): any change to iteration seeding or
   input interpolation shifts the numerical path of the SCC relaxation. It must be verified to
   preserve the converged steady state and the transient behavior documented in
   `executor_comparison.md`.

## Proposed Improvement

1. **Warm-start the SCC sub-step iteration**: seed each sub-step's model inputs/outputs from the
   latest committed values (previous sub-step or macro boundary) instead of the cold buffer
   state, so the fixed-point relaxation converges in fewer sub-iterations. Evaluate both:
   - (a) keeping the fixed iteration count but with warm seeding (numerical parity, per-call
     cost), and
   - (b) convergence-based early termination when the warm start makes the first iterations
     already satisfy the configured tolerance.
2. **Sub-step input interpolation**: evaluate using the latest SCC input value **and its
   forwarded derivative** (`La2DataAccessResolver` already forwards order-1 derivatives through
   `copy_connection`) to interpolate SCC inputs at sub-step boundaries, matching how
   `canInterpolateInputs` FMUs consume derivative data. Measure FMU internal-step counts with and
   without interpolation to quantify the speed-up.
3. **Evaluation gate**: for each variant, compare against the baseline la2 run on the embrace
   scenario — same steady state (t=200–2000 within the 0.09%/0.05% documented envelopes),
   same transient envelope, and per-call model walltime. Use `record_derivatives` output to
   confirm derivatives stay correctly anchored to the sub-step times.

## Expected Benefit

- Fewer sub-iterations per macro step → the hybrid's dominant cost drops toward the fine-step
  jacobi baseline (measured ~1.3–3.5× per-call inflation today).
- No change to the outer DAG scheduling or the executor family API — the la2 stack is
  self-contained (`la2_builder.cpp`, `LinearSubstepExecutor`, `La2DataAccessResolver`).
- Correctness stays verifiable: the new derivative-recording output makes timestep anchoring of
  inputs/derivatives directly observable.

## Risk And Blast Radius

- **Blast radius**: Moderate. Core of the la2 stack: `la2_builder.cpp`,
  `linear_substep_executor.cpp`, `la2_data_access_resolver.cpp`, `resolver_common.cpp`
  (copy_connection derivative forwarding already present). No changes to the flat jacobi/seidel
  families or the `Invocable` interface.
- **Numerical risk**: Warm-starting changes the relaxation path; parity with baseline la2
  (and with jacobi steady state) must be re-verified per the evaluation gate.
- **Determinism risk**: Low if iteration count stays fixed; Medium if convergence-based
  early termination is added (thread scheduling dependent).
- **Backward compatibility**: Full — opt-in via existing la2 config keys; default behavior
  unchanged until the change is proven.

## Suggested Priority

Medium — a performance optimization of the la2 family with a concrete evaluation gate and
verifiable artifacts (the timing analysis and derivative recording landed 2026-09-16).

## Task Contract Seed

1. Profile the la2 sub-step loop to quantify fixed-iteration vs warm-started cost on the embrace
   scenario (baseline in `resources/embrace/executor_timing_analysis.md`).
2. Implement warm seeding of sub-step inputs/outputs from latest committed values; keep
   iteration count fixed first; measure per-call model walltime and numerical parity.
3. If (2) is neutral or negative, evaluate convergence-based early termination behind the
   existing `la2.iterations` semantics (a positive value keeps fixed count; remove/negative
   enables early exit).
4. Evaluate sub-step input interpolation from latest value + forwarded derivative; measure FMU
   internal-step counts (`canInterpolateInputs`) with/without interpolation.
5. Verify with `simulation.recording.record_derivatives` that derivative values stay anchored to
   sub-step times; update `executor_timing_analysis.md` with results.
