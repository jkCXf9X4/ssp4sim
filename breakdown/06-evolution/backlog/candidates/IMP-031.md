# IMP-031: Implement OpenTelemetry Distributed Observability

## Status

Proposed

## Layer

05-operation (observability contract), 03-implementation (runtime integration)

## Theme

Add OpenTelemetry tracing for distributed simulations so cross-process execution can be observed as one correlated trace.

## Evidence

- `OD-005` defines OpenTelemetry as the distributed observability tier
- `UC-010` captures the distributed simulation use case
- Current logging sinks cover only local overview, archival JSON, and live cutelog navigation

## Proposed Improvement

1. Add OpenTelemetry span emission for key simulation phases and cross-component calls.
2. Define trace context propagation across simulation boundaries.
3. Attach stable metadata such as run id, scenario, component, storage, and simulation time.
4. Make the exporter and endpoint configurable without affecting local logging sinks.
5. Preserve the current local logging tiers as independent outputs.

## Tradeoffs

- OpenTelemetry gives distributed visibility that local logs cannot, but it adds protocol and backend configuration complexity.
- Trace data is more structured than log text, but it is not a replacement for local overview or deep-analysis logs.
- Standardized observability reduces backend lock-in compared with a custom remote logging protocol.

## Acceptance Criteria

- Distributed simulations can emit correlated traces.
- Trace context survives cross-process boundaries.
- OpenTelemetry can be enabled or disabled independently of local logging sinks.
- Documentation references `OD-005` as the canonical observability tier.
