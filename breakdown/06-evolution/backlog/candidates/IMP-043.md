# IMP-043: Unit Test Coverage for Boundary Connection Resolution

## Lifecycle Stage
Candidate

## Status
Proposed

## Evidence

`resolve_connection()` (lines 164–256) and `resolve_model_key()` (lines 145–159) in
`lib/include/graph/graph_builder.cpp` implement the core nested-SSP boundary-crossing
connection resolution algorithm. A search of `tests/` for both function names found
**zero** unit or integration tests. Coverage is entirely indirect via end-to-end fixture
tests (`dcmotor_nested`, `signal_nested_parameter_bindings`), which exercise only
a subset of the four resolution cases.

## Current Pain / Risk

- No regression protection for boundary resolution logic. Changes to the four cases in
  `resolve_connection()` or the suffix-matching algorithm in `resolve_model_key()`
  could silently break nested SSP simulation.
- Four resolution cases with direction symmetry (INPUT vs OUTPUT) are a frequent source
  of bugs — one was fixed during IMP-042 delivery (Case 3 boundary OUTPUT direction).
- The methods are private and currently have no test harness, making isolated
  testing impossible without a visibility change.

## Proposed Improvement

1. Make `resolve_model_key()` and `resolve_connection()` testable (protected +
   test subclass, or add a test-only friend / header).
2. Add `tests/lib/graph/test_graph_builder.cpp` with focused unit tests:
   - `resolve_model_key()`: exact match, suffix match, no match, empty input.
   - `resolve_connection()`: each of the 4 cases (direct FMU→FMU, source-system
     boundary INPUT, source-system boundary OUTPUT, target-system boundary),
     with constructed AnalysisConnection objects.
3. Optionally add integration tests using the existing `dcmotor_nested` and
   `signal_nested_parameter_bindings` fixtures that exercise all four cases.

## Expected Benefit

- Faster defect detection during refactoring or future nested-SSP enhancements.
- Explicit documentation of edge cases and expected resolution behavior.

## Risk / Blast Radius

Low-Medium — test files only; requires a minor visibility change (protected or
friend) in `graph_builder.hpp`. No production code behavior changes.

## Suggested Priority: Medium

## Task Contract Seed

- [ ] Decide on test-access mechanism (protected method + subclass, friend class,
      or extraction into a standalone utility).
- [ ] Add `resolve_model_key()` unit tests (exact, suffix, empty, no match).
- [ ] Add `resolve_connection()` unit tests (all 4 cases, boundaries, delays).
- [ ] Optionally add integration tests for systems exercising all four cases.
- [ ] Verify coverage: all branches of `resolve_connection()` and
      `resolve_model_key()` exercised. CI must pass.

## Out Of Scope

- Changes to behavior of `resolve_connection()` or `resolve_model_key()`.
- Production code changes beyond test-harness visibility adjustments.

## Notes

The Case 3 boundary-OUTPUT bug fixed during IMP-042 (revision iteration 1)
would have been caught by focused unit tests, demonstrating the value.
