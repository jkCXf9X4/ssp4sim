# IMP-030: Implement Remote Result Ingestion via InfluxDB Line Protocol

## Status

Proposed

## Layer

05-operation (remote ingestion contract), 03-implementation (recording sinks)

## Theme

Add a remote result sink that emits simulation results through the canonical
InfluxDB Line Protocol interface so multiple simulation sources can ingest into
a shared remote database.

## Evidence

- `OD-004` defines InfluxDB Line Protocol as the remote result interface
- `UC-006` captures the remote ingestion use case
- Current releases only support file-backed CSV and local database artifacts

## Proposed Improvement

1. Add a remote result sink that serializes result records as InfluxDB Line Protocol.
2. Define how simulation metadata maps to line protocol tags and fields.
3. Add batching, retry, and backpressure behavior for remote writes.
4. Make authentication and target endpoint configuration explicit.
5. Preserve CSV and local database behavior as the default local workflows.

## Tradeoffs

- Line protocol is compact and easy to batch, but the sink must still handle
  retries and partial failures cleanly.
- A remote sink enables multi-source ingestion and shared dashboards, but it
  adds operational dependencies that file-backed outputs avoid.
- The contract should stay wire-format focused so backend selection remains
  flexible.

## Acceptance Criteria

- Remote results can be exported through InfluxDB Line Protocol.
- Result metadata maps consistently to tags and fields.
- Remote write failures are surfaced clearly and do not corrupt local outputs.
- Documentation and configuration reference `OD-004` as the canonical remote
  interface.
