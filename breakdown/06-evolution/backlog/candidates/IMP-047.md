# IMP-047: Replace Vendored Reference SSPs with Small In-Repo E2E Fixtures

## Lifecycle Stage
Candidate

## Status
Proposed

## Evidence

- `resources/reference_ssp` is a git submodule pinned to
  `git@github.com:pyssporg/ssp_references.git` (root `.gitmodules`). It vendors the
  full curated model collection plus generated `artifacts/` and a nested Git tree.
- High-level workflow tests read fixtures straight out of it:
  `tests/python/high_level/_helpers.py` defines `REFERENCE_SSP_ROOT`
  (`resources/reference_ssp/artifacts/models`) and `SOURCE_SSP_ROOT`
  (`resources/reference_ssp/models/ssp`), and `discover_reference_ssps()` sweeps
  every experiment directory. `test_reference_sweep.py` and
  `test_parameter_sets.py` consume that discovery.
- C++ tests also hardcode the submodule artifacts, e.g.
  `tests/lib/core/test_fmi4c_adapter.cpp`,
  `tests/lib/core/test_parameter_binding_integration.cpp`,
  `tests/lib/analysis/test_tree_builder.cpp`,
  `tests/lib/analysis/test_graph_builder.cpp`,
  `tests/lib/simulation/test_graph_builder_dedup.cpp`,
  `tests/lib/simulation/test_simulation_lifecycle.cpp`, and
  `tests/lib/high_level/test_smoke_simulator.cpp` all build paths under
  `resources/reference_ssp/artifacts/models/...`.
- `tests/README.md` documents the reference sweep over
  `resources/reference_ssp/artifacts/models/*/*` and the fixture-management
  policy in `resources/reference_ssp/AGENTS.md`.
- `.github/workflows/linux-release.yml` checks out `submodules: recursive`, so
  every release job pulls the full reference collection.
- `ssp_references` already owns the authoritative reference models and
  cross-engine comparison tooling (`models/ssp`, `artifacts/`,
  `scripts/run_simulations.py`, `scripts/run_comparisons.py`).
- The current arrangement is a recorded decision: `breakdown/04-verification/
  decisions/VD-004.md` (Accepted) states reference SSP fixtures are static,
  version-controlled artifacts of this repository, and
  `breakdown/04-verification/test-strategy.md` names them "the primary workflow
  test data." This candidate supersedes VD-004 and must land with a new decision
  record that amends it.

## Current Pain / Risk

- **Wrong owner.** ssp4sim is the engine; `ssp_references` is the curated
  reference-model and cross-engine comparison repository. Vendoring the latter
  inside the former splits ownership and duplicates intent.
- **Heavy, brittle checkouts.** The submodule drags generated `artifacts/`, a
  nested Git tree, and build outputs into every clone and release job; editing
  it is governed by special rules because the content is generated elsewhere.
- **Non-hermetic tests.** ssp4sim's e2e surface changes whenever the submodule
  pointer moves. A test can go red because a fixture in another repo changed,
  not because the engine regressed.
- **Coupling of low-level tests.** C++ unit tests reach into generated reference
  artifacts for their inputs, so they inherit the submodule's availability and
  layout.

## Proposed Improvement

1. **Remove the vendored reference collection.** Drop the
   `resources/reference_ssp` submodule (`.gitmodules` entry, checkout, nested
   tree) and the `submodules: recursive` dependency on it. Keep the other
   `3rdParty/*` submodules.
2. **Add a small in-repo e2e fixture set.** Author a handful of tiny
   co-simulation SSPs under the repository's own `tests/resources/` (for
   example: a source→sink pair, a two-FMU graph, and one nested/boundary case)
   with committed expected outputs. This is enough to prove the top-level
   simulator path end to end without the full collection.
3. **Repoint the tests.** Point `_helpers.py` and the C++ tests listed above at
   the small fixtures; keep exactly one smoke/reference sweep over that set so
   the high-level layer stays a single path.
4. **Outsource the complete e2e.** Move the comprehensive reference sweep and
   result-comparison workflow to `ssp_references`, which already holds the
   models and comparison scripts. Add/confirm a CI job there that runs the full
   cross-engine e2e, so ssp4sim can be validated by it out of tree.
5. **Update the record.** Supersede `VD-004` with a new decision record,
   and update `breakdown/04-verification/test-strategy.md`,
   `breakdown/04-verification/ci-test-stages.md`, `tests/README.md`, and the
   root `readme.md` to state the new boundary: ssp4sim = small in-repo e2e;
   `ssp_references` = full cross-engine e2e.

## Expected Benefit

- Faster, hermetic clones and CI with no generated fixture artifacts.
- Clear ownership: ssp4sim tests its engine; `ssp_references` owns reference
  models and cross-engine validation.
- Engine regressions no longer masked by, or confused with, fixture changes in
  another repository.
- C++ unit tests depend only on small, local, stable fixtures.

## Risk / Blast Radius

Medium — removes a submodule, adds a small fixture set, and touches several C++
test files, Python high-level helpers, the CI checkout step, and the
verification-layer docs plus a superseding decision record. No production code
behavior changes.

- [ ] Author the small fixture set (source/sink, 2-FMU graph, one nested

      reference checkout in CI.
- [ ] Confirm `ssp_references` runs the full e2e (models + `run_comparisons.py`)
      and has a CI job for it; add one if missing.
- [ ] Write the superseding decision record for `VD-004`; update
      `test-strategy.md`, `ci-test-stages.md`, `tests/README.md`, `readme.md`.
- [ ] Verify: full ssp4sim suite green on the small fixtures; `ssp_references`
      e2e green and independent of ssp4sim.

## Out Of Scope

- Changing simulation behavior or public APIs.
- Authoring new reference models or cross-engine comparison logic (owned by
  `ssp_references`).
- Removing the `3rdParty/fmi4c` or `3rdParty/ssp4cpp` submodules.

## Notes

- `tests/README.md` already asks to "keep the C++ high-level layer to a single
  smoke path" and to put reference sweeps and comparison in pytest; shrinking
  ssp4sim to a small local fixture set is consistent with that guidance.
- `resources/reference_ssp/AGENTS.md` exists only because the fixtures live here;
  once the submodule is gone, that guidance belongs with `ssp_references`.
