# IMP-017: Deduplicate Test Pyramid Description Between Tests/Readme And PBS Strategy

## Status

Proposed

## Layer

04-verification

## Theme

The three-layer test pyramid (unit/integration/workflow) and its purpose are described in both `tests/README.md` and `product-breakdown/04-verification/test-strategy.md`. Differentiate them: PBS owns the strategic rationale, tests/README.md owns the concrete layout.

## Evidence

- `tests/README.md`, lines 14-28: Describes the three layers with file locations and purpose (Core C++ tests under `tests/lib/core/`, Utils C++ tests under `tests/lib/utils/`, High-level C++ smoke test, Python high-level tests).
- `product-breakdown/04-verification/test-strategy.md`, lines 11-18: Describes the same three layers with substantially similar purpose descriptions but adds the strategic rationale.

## Current Pain Or Risk

- **Blurred boundary**: A developer reading the PBS test strategy finds a description identical in spirit to the test README. The value of the PBS version is the strategic overlay (why layers exist, what each layer gates, the traceability to requirements), which gets mixed with concrete layout info.
- **Drift risk**: If a new test layer is added or a directory is renamed, both files need updates.

## Proposed Improvement

1. In `product-breakdown/04-verification/test-strategy.md`, condense the layer descriptions (lines 11-18) to strategic statements — why each layer exists, what quality attribute it targets, how it gates releases. Remove concrete file paths and test runner details (those belong in `tests/README.md`).
2. Add cross-links in both directions:
   - In `test-strategy.md`: "See `tests/README.md` for the concrete test layout and run commands."
   - In `tests/README.md`: "See `product-breakdown/04-verification/test-strategy.md` for the strategic rationale and test coverage targets."

## Expected Benefit

- Clean separation: strategy vs layout.
- Both files become easier to maintain independently.

## Risk And Blast Radius

- **Blast radius**: 2 files (test-strategy.md and tests/README.md). Minor text changes.
- **Risk**: Low. Text changes only.

## Suggested Priority

Low — existing duplication is stable and not high-drift.

## Task Contract Seed

The smallest scoped task:

1. Open `product-breakdown/04-verification/test-strategy.md`. Review lines 11-18 and replace any concrete file path or test runner detail with strategic rationale. Add a cross-link to `tests/README.md` for the concrete layout.
2. Open `tests/README.md`. Add a cross-link to `product-breakdown/04-verification/test-strategy.md` for the strategic test approach.

## Out Of Scope

- Do not restructure the test pyramid or add new layers.
- Do not change the test layout or directory structure.
