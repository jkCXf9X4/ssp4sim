# IMP-010: Remove Logging Guidelines From PBS Module Signal.md — They Do Not Belong There

## Status

Proposed

## Layer

03-implementation

## Theme

Remove verbatim-logged "Logger Construction" and "Quill Backend Profile" sections from `product-breakdown/03-implementation/modules/signal.md`, which describe global logging conventions unrelated to the signal module. Keep the canonical version in `docs/logging_guidlines.md` and cross-link from the PBS file.

## Evidence

- `docs/logging_guidlines.md` (90 lines): Contains the full logging guideline including level table, hot-path guidance, `IF_LOG` macro usage, Logger Construction (lines 49-55), and Quill Backend Profile (lines 79-90).
- `product-breakdown/03-implementation/modules/signal.md`, lines 43-58: Contains verbatim copies of the same Logger Construction bullet list and Quill Backend Profile. These have nothing to do with the signal/recording module — they are project-wide logging conventions.
- The module's Traceability section (line 40-41) does not reference `docs/logging_guidlines.md` as a source, so there is no cross-link to justify the inclusion.

## Current Pain Or Risk

- **Domain mismatch**: A developer reading the signal module documentation to understand recording internals encounters unrelated logging policy text. This undermines the module-as-boundary concept.
- **Drift risk**: Any update to logging guidelines (new Quill version, changed backend profile) must be made in two files.
- **No cross-reference**: Unlike other PBS files (configuration.md, profiling.md) which link to their `docs/` counterparts, signal.md just duplicates without attribution.

## Proposed Improvement

1. In `product-breakdown/03-implementation/modules/signal.md`, delete the "Logger Construction" subsection (lines 43-48) and the "Quill Backend Profile" subsection (lines 50-58).
2. Add a 1-2 sentence note after "Notable Patterns" (or as a new subsection) clarifying what logging patterns are specific to the signal module (e.g., "Signal components log storage operations at TRACE_L2, recorder dispatch at DEBUG"), and link to `docs/logging_guidlines.md` for general logger policy.
3. Preserve all signal-specific content (purpose, components, sinks, include boundary, dependencies, notable patterns).

## Expected Benefit

- module/signal.md becomes a focused description of the signal/recording subsystem.
- Single source of truth for logging guidelines (`docs/logging_guidlines.md`).
- Reduced drift risk.

## Risk And Blast Radius

- **Blast radius**: 2 files (`product-breakdown/03-implementation/modules/signal.md` and `docs/logging_guidlines.md`). PBS loses ~15 lines of duplicated content.
- **Risk**: Low. The removed text is a verbatim duplicate. No code, build, test, or CI changes.
- **Dependency**: None. No other PBS files reference signal.md's logging content.

## Suggested Priority

High — domain mismatch is a clear structural violation of module boundaries.
