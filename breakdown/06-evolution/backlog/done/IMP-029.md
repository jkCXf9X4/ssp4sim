# IMP-029: Implement SQLite WAL Local Database Sink

## Status

Done

## Layer

03-implementation (recording sinks), 01-product (result artifact model)

## Theme

Add a SQLite WAL local database sink so the primary local result artifact can
serve live one-writer, many-reader viewer workflows without repeated CSV scans.

## Evidence

Current support is limited to file-backed sinks:

- `CsvRecorderSink` writes portable row-oriented CSV output
- `OD-002` states that streaming, socket, and network output are unavailable

## Proposed Improvement

1. Add a SQLite WAL local database sink for live local viewer workflows.
2. Define common result metadata across local database sinks: run id, model,
   storage, variable, timestamp, simulation time, and source identity.
## Tradeoffs

- SQLite WAL is simple and supports concurrent local readers, but it will lose
  to columnar engines for large historical scans.
- CSV remains valuable as the lowest-friction export even when database sinks
  are enabled.

## Acceptance Criteria

- Product docs describe the primary local database artifact without overstating
  current implementation.
- Local database sink selection is explicit in configuration.
- Existing CSV behavior remains compatible by default.
