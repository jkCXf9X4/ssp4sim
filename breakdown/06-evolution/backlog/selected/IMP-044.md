## Theme

Test code quality and coverage improvement for `tests/lib/graph/test_sim_graph_builder.cpp`

## Evidence

- `tests/lib/graph/test_sim_graph_builder.cpp` (325 lines, 6 TEST_CASE blocks, 8 SECTION blocks)
- Plan file: `.opencode/dev_harness_plans/2026-07-03_070248-REFACTOR-TEST-SIM-GRAPH-BUILDER.md`
- Overlapping test: `tests/lib/model/test_model_connection.cpp`

## Current Pain Or Risk

1. **Repeated boilerplate (8 instances)**: `SignalStorage` creation, `add()`, `allocate()` pattern duplicated 8+ times. Each repetition is 3-5 lines that could be 1-2 lines. Copy-paste errors risk inconsistent test setup.

2. **Repeated ConnectionInfo setup (5 instances)**: 8-line struct field assignment repeated 5+ times. High copy-paste surface area; any new field on ConnectionInfo must be manually propagated.

3. **Repeated memcpy read pattern (6 instances)**: 3-line `memcpy`+`CHECK` boilerplate repeated 6+ times. Obscures test intent behind low-level memory operations.

4. **Dead setup in empty-connections test**: Lines 157-163 create and allocate SignalStorage instances that are never used. Misleading for readers.

5. **Tautological feedthrough test (entire TEST_CASE, lines 293-325)**: Tests that `ft_con.is_feedthrough = (ft_con.delay == 0)` followed by `CHECK(ft_con.is_feedthrough == true)` — this tests only the local assignment expression, not any production code. Overlaps with `test_model_connection.cpp` which already covers `ConnectionInfo::is_feedthrough` field behavior.

6. **Missing coverage**: Methods like `ConnectionInfo::forward_derivatives`, `forward_derivatives_order`, `ConnectorInfo::set_start_values`, `write_data_to_model`, `read_values_from_model`, `apply_input_derivatives`, `fetch_output_derivatives`, multiple simultaneous connections, edge-case delays, and out-of-bounds indices are untested.

7. **Misleading file name**: File is named `test_sim_graph_builder.cpp` but tests `ConnectionInfo` and `ConnectorInfo` methods, not the `SimGraphBuilder` class itself.

## Proposed Improvement

Consolidated refactoring of `tests/lib/graph/test_sim_graph_builder.cpp`:

1. **Extract helper functions** (file-local, anonymous namespace):

   a. `make_storage(name, type, areas)` — replaces repeated `SignalStorage` creation + `add()` + `allocate()` pattern (items 2, 5 in the plan).

   b. `make_connection(src, tgt, type, src_idx, tgt_idx, delay)` — replaces repeated `ConnectionInfo` struct field assignment pattern (item 3).

   c. `read_storage_value<T>(storage, area, index)` — replaces repeated `memcpy` + `CHECK` pattern (item 4).

2. **Remove dead setup code**: Delete unused `src` and `tgt` SignalStorage creation in the "Empty connections list is a no-op" section (item 5).

3. **Fix tautological feedthrough test** (items 7, 11): Either (a) remove the overlapping TEST_CASE and consolidate feedthrough tests in `test_model_connection.cpp`, (b) replace with a test that actually exercises `wire_connections` or the production code path, or (c) add a clarifying comment explaining what production path is simulated.

4. **Add missing test coverage** (item 10): Add focused TEST_CASE blocks for untested methods. Prioritize by production risk.

5. **Clarify file scope**: Either rename the file to match its content (e.g., `test_model_connection_extended.cpp`) or add a file-level comment clarifying that it tests ConnectionInfo/ConnectorInfo helper methods used by SimGraphBuilder.

## Expected Benefit

- Reduced boilerplate: ~40 lines removed, replaced by ~15 lines of reusable helpers
- Clearer test intent: helpers communicate "what" not "how" (e.g., `read_storage_value<double>(tgt, area, 0) == 42.0` instead of `memcpy` boilerplate)
- Reduced copy-paste error surface: changes to ConnectionInfo fields propagate from one factory function
- Eliminated misleading test: tautological assertions removed, replaced with real coverage or clarified intent
- Filled verification gaps: untested methods gain basic coverage
- Clearer code organization: file name or comment signals what the file actually tests

## Risk And Blast Radius

- Low risk overall — test-only changes. No production code affected.
- Helper extraction changes ~30 lines across the file; risk is introduction of bugs in helper functions (mitigated by tests).
- Removing the feedthrough TEST_CASE could hide intent if the test was meant to validate a specific wiring path. Option (c) in item 3 is safest.
- Adding coverage increases maintenance surface but is proportional to production risk.
- File rename would require updating CMakeLists.txt references and potentially CI cache invalidation. Comment-only change has zero blast radius.
